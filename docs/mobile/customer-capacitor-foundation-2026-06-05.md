# PetWash Customer App Capacitor Foundation

Date: 2026-06-05

## Status

The Customer App now has a separate Capacitor foundation stacked on the Provider App foundation:

- Customer config template: `config/capacitor/customer.config.ts`
- iOS native project: `ios-customer/App/App.xcodeproj`
- Android native project: `android-customer/`
- Customer bundle id / application id: `il.co.petwash.customer`
- Display name: `PetWash Customer`
- Web bundle source: `dist/public`
- Official Capacitor package line: v8

The root `capacitor.config.ts` is restored to the Provider app by default after app-specific commands. Customer commands use `scripts/mobile/run-capacitor-app.mjs`, which selects the Customer config, runs the requested Capacitor action, and restores the Provider config in a `finally` block.

## Native Plugins In Foundation

The Customer foundation includes only official Capacitor plugins:

- `@capacitor/app` for app lifecycle and deep-link handling foundation
- `@capacitor/camera` for future pet photos, support attachments, and supported station/service code scans
- `@capacitor/push-notifications` for future booking, session, receipt, and support notifications
- `@capacitor/splash-screen`
- `@capacitor/status-bar`

Biometric unlock, native Sign in with Apple, production push certificates, and store signing are intentionally not implemented in this first customer PR.

## Security And Store Guardrails

- No `server.url` is set in the Customer Capacitor config.
- iOS bundle id is `il.co.petwash.customer`.
- Android application id and namespace are `il.co.petwash.customer`.
- Android backup is disabled by default with `android:allowBackup="false"` and `android:fullBackupContent="false"`.
- Android declares `POST_NOTIFICATIONS` and `CAMERA` permissions for the linked plugin lane.
- iOS declares `NSCameraUsageDescription` and `NSPhotoLibraryUsageDescription`.
- No signing certificates, provisioning profiles, keystores, Firebase `GoogleService-Info.plist`, or Android `google-services.json` files are committed.
- Copied web assets under `ios-customer/App/App/public` and `android-customer/app/src/main/assets/public` are ignored and regenerated by `npm run cap:customer:sync`.
- `npm run cap:customer:sync` prunes generated `.map` files from `dist/public` and native copied web assets so hidden Vite source maps are not packaged into mobile builds.

## Developer Workflow

From the repo root:

```sh
npm install
npm run cap:customer:sync
npm run cap:customer:open:ios
npm run cap:customer:open:android
```

For non-GUI verification:

```sh
npm run build
node scripts/mobile/select-capacitor-config.mjs customer
npx cap sync
npm run cap:clean-sourcemaps
node scripts/mobile/select-capacitor-config.mjs provider
xcodebuild -list -project ios-customer/App/App.xcodeproj
```

## Not Ready Yet

This foundation does not make the Customer App ready for TestFlight, App Store Connect, Google Play, or public submission. The remaining lanes are:

- Apple Developer team id and provisioning profiles
- Android signing keystore and Play App Signing setup
- Firebase iOS/Android app registrations and native config files
- APNs and FCM push setup
- Native deep-link URL scheme and universal/app links validation
- Real device QA for signup/login, account deletion, booking, K9000 session flow, receipts, camera, push, offline/poor-network behavior, and role separation
- Store privacy labels / Data safety answers matched to production behavior
