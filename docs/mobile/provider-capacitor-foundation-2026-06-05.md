# PetWash Provider App Capacitor Foundation

Date: 2026-06-05

## Status

The Provider App now has a real Capacitor foundation in the main PetWash repo:

- Root Capacitor config: `capacitor.config.ts`
- iOS native project: `ios/App/App.xcodeproj`
- Android native project: `android/`
- Provider bundle id / application id: `il.co.petwash.provider`
- Display name: `PetWash Provider`
- Web bundle source: `dist/public`
- Official Capacitor package line: v8

Xcode verification passed with:

```sh
xcodebuild -list -project ios/App/App.xcodeproj
```

The project exposes the `App` target and `App` scheme, plus the first-party Capacitor plugin schemes.

## Native Plugins In Foundation

The foundation includes only official Capacitor plugins:

- `@capacitor/app` for app lifecycle and deep-link handling foundation
- `@capacitor/camera` for future provider verification/service documentation capture
- `@capacitor/push-notifications` for future provider job/status notifications
- `@capacitor/splash-screen`
- `@capacitor/status-bar`

Biometric login, Sign in with Apple native flows, production push certificates, and app-store signing are intentionally not implemented in this first PR. Those require separate secrets, console setup, entitlements, and device validation.

## Security And Store Guardrails

- No `server.url` is set in Capacitor config, so the shell uses the bundled production web assets instead of a hard-coded live host.
- iOS bundle id is `il.co.petwash.provider`.
- Android application id and namespace are `il.co.petwash.provider`.
- Android backup is disabled by default with `android:allowBackup="false"` and `android:fullBackupContent="false"`.
- Android declares `POST_NOTIFICATIONS` and `CAMERA` permissions for the linked plugin lane.
- iOS declares `NSCameraUsageDescription` and `NSPhotoLibraryUsageDescription`.
- No signing certificates, provisioning profiles, keystores, Firebase `GoogleService-Info.plist`, or Android `google-services.json` files are committed.
- Copied web assets under `ios/App/App/public` and `android/app/src/main/assets/public` are ignored and regenerated by `npm run cap:provider:sync`.
- `npm run cap:provider:sync` prunes generated `.map` files from `dist/public` and native copied web assets so hidden Vite source maps are not packaged into mobile builds.

## Developer Workflow

From the repo root:

```sh
npm install
npm run cap:provider:sync
npx cap open ios
npx cap open android
```

For non-GUI verification:

```sh
npm run build
npx cap sync
xcodebuild -list -project ios/App/App.xcodeproj
```

## Not Ready Yet

This foundation does not make the Provider App ready for TestFlight, App Store Connect, Google Play, or public submission. The remaining lanes are:

- Apple Developer team id and provisioning profiles
- Android signing keystore and Play App Signing setup
- Firebase iOS/Android app registrations and native config files
- APNs and FCM push setup
- Native deep-link URL scheme and universal/app links validation
- Real device QA for login, provider onboarding, camera, push, offline/poor-network behavior, and account deletion
- Store privacy labels / Data safety answers matched to production behavior
