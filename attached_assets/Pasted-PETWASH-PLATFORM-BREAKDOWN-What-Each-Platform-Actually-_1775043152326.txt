PETWASH - PLATFORM BREAKDOWN  
What Each Platform Actually Does

==================================================
0. FIRST RULE - PLATFORM ≠ SCREEN
==================================================

A platform is not a page or app.  
A platform is:

- a context
- a set of rules
- a set of permissions
- a type of user behavior
- a type of transaction

If you design platforms as “screens”, you will fail.  
If you design them as systems with purpose, it will work.

==================================================
1. KIOSK PLATFORM (PHYSICAL SYSTEM)
==================================================

WHAT IT IS
Physical dog-wash stations connected to backend.

WHAT IT DOES
- starts and controls wash sessions
- receives payment authorization
- executes real-world action (water, soap, dryer)
- sends session events back to backend

CORE BEHAVIOR
- instant usage
- no scheduling
- real-time response
- hardware-triggered lifecycle

FLOW
User arrives → scan QR / tap → validate funds → reserve → start session → complete → finalize

KEY RULES
- must be idempotent (same signal cannot trigger twice)
- must not start without guaranteed payment
- must handle retries safely
- must log every session

WHAT CAN BREAK
- double start
- no payment but session starts
- duplicate callbacks
- hardware failure mid-session

SYSTEM RESPONSIBILITY
- backend decides if allowed
- kiosk only executes

==================================================
2. LOYALTY / CLUB PLATFORM (GROWTH ENGINE)
==================================================

WHAT IT IS
Public membership system for all users.

WHAT IT DOES
- onboarding new users
- managing wallet
- managing rewards and benefits
- showing history and usage
- driving retention

CORE BEHAVIOR
- low friction
- mobile-first
- instant value after signup

FLOW
Signup → verify → create wallet → assign membership → show dashboard

KEY RULES
- no KYC required
- wallet must exist immediately
- user must land in usable state
- consent must be explicit

WHAT CAN BREAK
- signup loops
- no wallet after signup
- wrong routing (provider flow)
- hidden consent

SYSTEM RESPONSIBILITY
- unify identity
- attach correct role
- initialize financial state

==================================================
3. SERVICES PLATFORM (MARKETPLACE)
==================================================

WHAT IT IS
Booking system for pet services.

SERVICES
- sitters
- walkers
- trainers

WHAT IT DOES
- allows scheduling
- connects users with providers
- manages availability and booking lifecycle
- handles cancellations and changes

CORE BEHAVIOR
- time-based
- provider-dependent
- multi-step lifecycle

FLOW
Search → select provider → choose time → validate → reserve → confirm → complete

KEY RULES
- must not confirm without provider availability
- must reserve funds before confirming
- must handle cancellation rules
- must support partial refunds

WHAT CAN BREAK
- double booking
- no provider but confirmed booking
- payment mismatch
- cancellation inconsistency

SYSTEM RESPONSIBILITY
- coordinate user + provider + time + payment
- maintain booking state machine

==================================================
4. PROVIDER PLATFORM (SUPPLY SIDE)
==================================================

WHAT IT IS
System for service providers.

WHAT IT DOES
- onboarding providers
- verifying identity and documents
- managing availability
- receiving bookings
- communicating with users

CORE BEHAVIOR
- high trust
- controlled access
- staged onboarding

FLOW
Apply → processing → review → approved → active → receive jobs

KEY RULES
- must not allow unapproved providers to operate
- onboarding must not block or lose data
- resubmissions must be possible
- support must see full history

WHAT CAN BREAK
- stuck applications
- lost uploads
- unclear rejection reasons
- provider access before approval

SYSTEM RESPONSIBILITY
- enforce trust
- maintain provider state machine
- expose only allowed capabilities

==================================================
5. WALLET PLATFORM (FINANCIAL CORE)
==================================================

WHAT IT IS
Internal financial system.

WHAT IT DOES
- holds user balance
- processes credits and debits
- supports wallet + external payments
- records every transaction

CORE BEHAVIOR
- deterministic
- auditable
- consistent across all platforms

FLOW
Top-up → available balance → reserve → commit → release / refund

KEY RULES
- never go negative
- every change must be logged
- reservation must happen before usage
- refunds must restore correctly

WHAT CAN BREAK
- mismatch between UI and DB
- double deduction
- missing refund
- incorrect balance after failure

SYSTEM RESPONSIBILITY
- be the single source of financial truth

==================================================
6. COUPON / PROMOTION PLATFORM
==================================================

WHAT IT IS
Campaign and discount engine.

WHAT IT DOES
- define promotions
- validate eligibility
- apply discounts
- track usage

CORE BEHAVIOR
- rule-based
- limited usage
- context-aware

FLOW
Enter code → validate → apply → redeem → record

KEY RULES
- backend-only validation
- atomic redemption
- strict limits
- clear stackability

WHAT CAN BREAK
- double redemption
- unlimited usage
- wrong discount applied
- financial leakage

SYSTEM RESPONSIBILITY
- enforce campaign rules
- protect business margins

==================================================
7. ADMIN / OPERATIONS PLATFORM
==================================================

WHAT IT IS
Internal control system.

WHAT IT DOES
- manage providers
- manage campaigns
- view system state
- intervene when needed

CORE BEHAVIOR
- clarity
- auditability
- actionability

TOOLS
- queues
- dashboards
- filters
- actions (approve, reject, message, refund)

KEY RULES
- every action must be logged
- no hidden changes
- no silent overrides

WHAT CAN BREAK
- lack of visibility
- wrong approvals
- no audit trail

SYSTEM RESPONSIBILITY
- keep system running smoothly

==================================================
8. COMMUNICATION PLATFORM
==================================================

WHAT IT IS
Messaging and notification system.

WHAT IT DOES
- send SMS
- send email
- send push notifications
- manage in-app messages

TYPES
- transactional (booking, payment)
- operational (review, resubmission)
- marketing (campaigns)

KEY RULES
- marketing requires consent
- transactional must always send
- all messages must be logged

WHAT CAN BREAK
- sending without consent
- duplicate messages
- lost notifications

SYSTEM RESPONSIBILITY
- ensure users are informed
- ensure compliance

==================================================
9. PAYMENT INTEGRATION PLATFORM
==================================================

WHAT IT IS
External processor integration (Nayax, Shift4, etc.)

WHAT IT DOES
- process card payments
- confirm transactions
- send callbacks

CORE BEHAVIOR
- async
- external dependency
- must be verified

KEY RULES
- never trust single callback blindly
- must be idempotent
- must reconcile with internal ledger

WHAT CAN BREAK
- duplicate callbacks
- missing confirmation
- mismatch with wallet

SYSTEM RESPONSIBILITY
- safely integrate external money flow

==================================================
10. HOW EVERYTHING CONNECTS
==================================================

Example:

User books sitter for a week:

- Loyalty platform → user identity
- Services platform → booking logic
- Coupon platform → discount
- Wallet platform → partial payment
- Payment platform → remaining charge
- Provider platform → assign provider
- Communication platform → notifications
- Admin platform → visibility

ALL must work together.

==================================================
11. FINAL UNDERSTANDING
==================================================

Each platform:
- has its own job
- has its own rules
- has its own risks

But they must behave like one system.

If one platform lies (wallet, coupon, provider state),  
the entire product loses trust.
