--------------------------------------------------
5) USER SEGMENTATION (CRITICAL)
--------------------------------------------------

There are 5 completely different user classes:

1) Public Customer
2) Loyalty Member
3) Provider
4) Staff
5) Management / Admin

Each has:
- Separate onboarding
- Separate dashboards
- Separate permissions
- Separate data access

If you mix these, the architecture collapses.

--------------------------------------------------
6) PROVIDER MODEL (MADPAWS / ROVER STYLE)
--------------------------------------------------

Providers are NOT customers.

They are contractors.

They require:

- Full profile
- KYC
- ID verification
- Insurance declaration
- Background checks (if required)
- Admin approval

They must NOT:
- Accept jobs
- Appear in marketplace
- Receive payouts

Until approved.

--------------------------------------------------
7) STAFF & MANAGEMENT MODEL
--------------------------------------------------

No public admin creation.
No self-activation.
No role escalation.

Staff and management must:

- Request access
- Be approved
- Use MFA or Passkeys
- Have strict route protection

All actions must be logged in audit logs.
