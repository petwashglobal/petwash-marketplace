Yes. This is a real issue.

The good news:
	•	provider submission flow is now operationally correct
	•	it is async
	•	it does not block submit
	•	failures do not lose the application

The bad news:
	•	the identity verification itself is not strong enough
	•	this is not true KYC
	•	right now it is closer to face presence + image quality check, not real identity proof

Plain business truth

What you have now can answer:
	•	did the selfie contain one face?
	•	did the ID image contain one face?
	•	were the images blurry / too dark?
	•	did the async process complete safely?

What it cannot honestly answer:
	•	is this the same person?
	•	is this a live human?
	•	is this really a passport / ID / licence with extracted fields?
	•	does the document name / DOB / expiry match the provider profile?

So from a business and risk view:

Current status
	•	Submission pipeline: good
	•	Real provider verification: not enough

What this means commercially

If you launch providers on this as-is, you are relying on:
	•	document upload
	•	selfie upload
	•	weak landmark comparison

That may be okay for:
	•	low-risk soft onboarding
	•	manual review queue

It is not okay if you want to say:
	•	“verified provider”
	•	“KYC completed”
	•	“identity matched”

Correct next step

Do not throw away the current pipeline.
Keep it.

But change the logic from:

auto-approve on weak biometric score

to:

pending review until real verification exists

Best operating model right now

Public users
	•	no biometric
	•	no ID
	•	normal signup only

Providers
	•	upload ID
	•	upload selfie
	•	application saved immediately
	•	async processing runs after submit
	•	status remains:
	•	pending_review
	•	not approved
until real verification is added

What is missing technically

1. Document OCR wiring

The OCR service exists but is not connected to provider apply flow.

Must add:
	•	document type detection
	•	field extraction:
	•	full name
	•	DOB
	•	document number
	•	expiry date

2. Real face match

Current geometry comparison is not enough.

Need one of:
	•	AWS Rekognition CompareFaces
	•	Azure Face API
	•	Onfido / Veriff / Sumsub
	•	another real identity/KYC provider

3. Liveness

This is totally missing.

Need:
	•	selfie liveness challenge
	•	or vendor-based liveness
	•	or manual review only until implemented

4. Driver licence support

Currently not real support.
If licence is required, you need proper OCR / barcode / PDF417 handling depending on country.
