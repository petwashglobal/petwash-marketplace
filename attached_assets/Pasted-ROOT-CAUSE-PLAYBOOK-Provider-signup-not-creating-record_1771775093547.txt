APPROACH A (BEST, MOST STABLE): Firebase Hosting rewrite /api -> Cloud Run
Why:
- Same origin, no CORS issues
- Works on iOS Safari reliably
- No VITE_PRODUCTION_API_URL mistakes
- Cleanest long-term

firebase.json
- Replace serviceId + region with your real Cloud Run service name and region:
{
  "hosting": {
    "public": "dist",
    "ignore": ["firebase.json", "**/.*", "**/node_modules/**"],
    "rewrites": [
      {
        "source": "/api/**",
        "run": {
          "serviceId": "petwash-backend",
          "region": "me-west1"
        }
      },
      { "source": "**", "destination": "/index.html" }
    ]
  }
}

P0 - STOP LYING "OFFLINE" UI ERROR (must fix)

This is wrong and hides the real issue.

P0 - WHY PROVIDER RECORDS ARE NOT CREATED (failure matrix)
Provider record creation can fail at 7 layers:

LAYER 1: Frontend cannot reach backend
Symptoms:
- 503 on petwash.co.il/api/*
Fix:
- Hosting rewrite OR correct production API base

LAYER 2: Backend rejects due to auth token missing/invalid
Symptoms:
- 401 on create provider application
Fix:
- ensure Firebase ID token is sent
- ensure backend verifyFirebaseToken uses correct project keys
- ensure Authorized Domains include petwash.co.il in Firebase Auth

LAYER 3: Backend route not deployed or wrong path
Symptoms:
- 404 or unexpected HTML
Fix:
- deploy backend, verify route registration in routes.ts
- verify Cloud Run service is receiving /api routes

LAYER 4: Database missing migrations in production
Symptoms:
- backend returns 500 with "relation does not exist" or missing column
Fix:
- run migrations against PROD Neon (db:push)
- confirm tables exist: providers/provider_profiles/provider_applications/mfa_enrollments etc.

LAYER 5: Transaction fails (validation / constraints / duplicates)
Symptoms:
- 400/409
Fix:
- ensure idempotency keys on form submissions
- enforce unique indexes safely (email, phone) with friendly error
- do not create provider profile without user row existing

LAYER 6: External service fails (SendGrid/Sheets/Places)
Symptoms:
- 500 if not isolated, or form stuck
Fix:
- provider creation must succeed even if email/sheets fail
- external calls must be async or best-effort with retry queue
- do not block onboarding on Google Places autocomplete (manual fallback must still save)

LAYER 7: Routing/onboarding state machine broken
Symptoms:
- user created, but not redirected properly, or stuck in loop
Fix:
- server-driven post-login returns requiredActions and nextPath
- store onboarding status in DB, not only localStorage
- enforce onboarding gates server-side
