PHASE 4.1 - REMEDIATION INTELLIGENCE, DRILL-THROUGH ACTIONS & OPERATING REVIEW

GOAL
Move from self-assessment into guided corrective action.
The platform should now:
- score the confidence of recommended actions
- let finance leads move directly from command-center signals into the right workflow
- generate remediation plans instead of just surfacing issues
- balance approval workload before bottlenecks form
- measure governance delivery quality
- rank scenario quality over time
- assemble a monthly operating review pack for finance leadership

LOCKED PRINCIPLES
- no wallet-core changes
- no mutation of original financial facts
- all recommendations remain explainable
- no direct financial mutation from a recommendation without an approved workflow
- drill-through actions must route into existing audited endpoints
- balancing is assignment guidance first, not forced reassignment by default
- delivery analytics are observational before they become gating
- operating review packs must be deterministic and reproducible

==================================================
4.1A - ACTION RECOMMENDATION CONFIDENCE SCORING
==================================================

GOAL
Score how confident the platform is that a suggested action is the correct next move.

DB
Create table: recommendation_scores
- id SERIAL PRIMARY KEY
- recommendation_type VARCHAR(64) NOT NULL
- target_entity_type VARCHAR(64) NOT NULL
- target_entity_id VARCHAR(128) NOT NULL
- confidence_score NUMERIC(5,2) NOT NULL DEFAULT 0
- impact_score NUMERIC(5,2) NOT NULL DEFAULT 0
- urgency_score NUMERIC(5,2) NOT NULL DEFAULT 0
- explanation_json JSONB NOT NULL DEFAULT '{}'::jsonb
- created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()

Indexes
- recommendation_type
- target_entity_type
- target_entity_id
- created_at DESC

BACKEND
1. GET /api/prestige-pass/admin/wallet/recommendation-scores
Filters:
- recommendationType
- targetEntityType
- from
- to

2. POST /api/prestige-pass/admin/wallet/recommendation-scores/recompute
Logic:
- evaluate current recommendation signals
- compute:
  - confidence_score
  - impact_score
  - urgency_score
- write explanation_json with factor breakdown

3. GET /api/prestige-pass/admin/wallet/recommendation-scores/:entityType/:entityId
Returns latest recommendation stack for one entity

FRONTEND
Command Center
- recommendation cards show:
  - confidence %
  - urgency
  - expected impact
- explanation popover:
  - why the score is high or low

ACCEPTANCE
- score is deterministic for same source data
- explanation is human-readable
- no recommendations execute directly

==================================================
4.1B - COMMAND-CENTER DRILL-THROUGH WORKFLOWS
==================================================

GOAL
Every command-center signal should open the exact workflow needed to resolve it.

DB
No new table required

BACKEND
No new financial source-of-truth routes required if existing workflows cover resolution.
Optional helper endpoint:
GET /api/prestige-pass/admin/wallet/command-center/drillthrough/:widgetKey
Returns:
- targetTab
- targetEntityType
- targetEntityId
- suggestedAction
- actionUrl

Widget mappings:
- criticalAlerts -> alerts tab + alert detail
- pendingApprovals -> approvals queue
- staleReconExceptions -> reconciliation exceptions tab
- orchestrationFailures -> orchestration runs tab
- disputeEscalations -> disputes drawer
- closeBlocked -> finance close detail
- forecastPressure -> forecast tab
- anomalyClusters -> cluster detail

FRONTEND
Command Center tab
- every KPI tile becomes clickable
- deep-link into:
  - disputes
  - orchestration
  - approvals
  - reconciliation exceptions
  - finance close
- preserve filters in URL or local state

ACCEPTANCE
- every tile has a working drill-through
- destination opens on the right entity/filter
- no dead-end widgets

==================================================
4.1C - AUTO-GENERATED REMEDIATION PLANS
==================================================

GOAL
For major issue classes, show a step-by-step suggested remediation plan.

DB
Create table: remediation_plans
- id SERIAL PRIMARY KEY
- issue_type VARCHAR(64) NOT NULL
- target_entity_type VARCHAR(64) NOT NULL
- target_entity_id VARCHAR(128) NOT NULL
- plan_json JSONB NOT NULL
- confidence_score NUMERIC(5,2) NOT NULL DEFAULT 0
- created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
- status VARCHAR(24) NOT NULL DEFAULT 'suggested'   // suggested | accepted | dismissed | completed

Indexes
- issue_type
- target_entity_type
- target_entity_id
- status
- created_at DESC

BACKEND
1. GET /api/prestige-pass/admin/wallet/remediation-plans
2. POST /api/prestige-pass/admin/wallet/remediation-plans/generate
Input examples:
- stale_hold
- failed_remittance
- blocked_close
- breached_dispute
- reconciliation_exception

Output example:
{
  "steps": [
    "Open booking audit",
    "Verify wallet hold amount",
    "Release hold if provider unresponsive",
    "Notify affected user"
  ],
  "linkedActions": [
    { "label": "Open Booking Audit", "actionUrl": "..." }
  ]
}

3. PATCH /api/prestige-pass/admin/wallet/remediation-plans/:id
Actions:
- accept
- dismiss
- complete

FRONTEND
Command Center / Governance
- remediation drawer for each major issue
- step list with linked actions
- accept / dismiss / complete buttons

ACCEPTANCE
- plan content matches issue type
- linked actions route into real workflows
- plan lifecycle is tracked

==================================================
4.1D - APPROVAL WORKLOAD BALANCING
==================================================

GOAL
Reduce approval bottlenecks by showing workload imbalance and suggesting reassignment.

DB
Create table: approval_workload_snapshots
- id SERIAL PRIMARY KEY
- snapshot_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
- approver_uid VARCHAR(128) NOT NULL
- open_count INTEGER NOT NULL DEFAULT 0
- avg_age_hours NUMERIC(8,2) NOT NULL DEFAULT 0
- overdue_count INTEGER NOT NULL DEFAULT 0
- recommended_rebalance BOOLEAN NOT NULL DEFAULT false
- detail_json JSONB NOT NULL DEFAULT '{}'::jsonb

Indexes
- snapshot_at DESC
- approver_uid

BACKEND
1. GET /api/prestige-pass/admin/wallet/approval-workload
Returns:
- byApprover[]
- totalOpen
- mostLoadedApprover
- leastLoadedApprover
- suggestedReassignments[]

2. POST /api/prestige-pass/admin/wallet/approval-workload/rebalance-preview
Input:
- requestId
- targetApproverUid
Returns preview only:
- current owner
- target owner
- age
- reason

3. POST /api/prestige-pass/admin/wallet/approval-workload/reassign
- finance_admin only
- explicit reassignment
- writes finance_audit_log

FRONTEND
Orchestration or Policies tab
- workload heatmap/list
- rebalance suggestions
- reassign button with confirmation

ACCEPTANCE
- workload stats derive from live approval requests
- preview shows exact reassignment effect
- reassignment fully audited

- detail_json JSONB NOT NULL DEFAULT '{}'::jsonb

Indexes
- pack_type
- audience_name
- sent_at DESC

BACKEND
1. GET /api/prestige-pass/admin/wallet/governance-delivery-analytics
Filters:
- packType
- audienceName
- from
- to

2. POST /api/prestige-pass/admin/wallet/governance-delivery-analytics/recompute
Logic:
- aggregate from governance_pack_log
- compute delivery rate and failure rate

FRONTEND
Governance tab
- delivery KPI row:
  - sent
  - delivered
  - failed
  - delivery rate
- analytics table by audience and pack type
- worst-performing audience callout

ACCEPTANCE
- analytics reconcile to governance pack logs
- delivery rate math is consistent
- failures are clearly surfaced

4.1F - SCENARIO LIBRARY QUALITY RANKING
==================================================

GOAL
Rank reusable scenarios by usefulness and outcome quality.

DB
Create table: scenario_quality_scores
- id SERIAL PRIMARY KEY
- scenario_id INTEGER NOT NULL
- reuse_count INTEGER NOT NULL DEFAULT 0
- avg_backtest_score NUMERIC(8,2) NOT NULL DEFAULT 0
- avg_entity_score NUMERIC(8,2) NOT NULL DEFAULT 0
- quality_rank VARCHAR(16) NOT NULL DEFAULT 'unranked'   // gold | silver | bronze | unranked
- detail_json JSONB NOT NULL DEFAULT '{}'::jsonb
- updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()

Indexes
- scenario_id
- quality_rank
- updated_at DESC

BACKEND
1. GET /api/prestige-pass/admin/wallet/scenario-quality
2. POST /api/prestige-pass/admin/wallet/scenario-quality/recompute
Logic:
- combine:
  - template reuse count
  - forecast backtest score
  - entity impact score
- assign rank

FRONTEND
Simulation tab
- scenario quality badges
- ranking table
- top scenario callout
- sort by rank / reuse / score

ACCEPTANCE
- rank is reproducible from source metrics
- quality score is explainable
- reusable scenarios surface first

==================================================
4.1G - MONTHLY OPERATING REVIEW PACK
==================================================

GOAL
Create one operational review pack for finance leadership that combines execution, governance, and outcomes.

DB
Optional cache table:
operating_review_packs
- id SERIAL PRIMARY KEY
- month VARCHAR(7) NOT NULL
- pack_json JSONB NOT NULL
- signature VARCHAR(255) NOT NULL
- generated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
- UNIQUE(month)

BACKEND
1. GET /api/prestige-pass/admin/wallet/operating-review-pack?month=YYYY-MM
Returns:
- finance close summary
- settlement summary
- payout release stats
- approval bottlenecks
- governance delivery analytics
- scenario quality summary
- anomaly cluster summary
- recommendation confidence summary
- commentary rollup
- signature

2. GET /api/prestige-pass/admin/wallet/operating-review-pack/export?month=YYYY-MM
- deterministic JSON export
- optional CSV summary sections

FRONTEND
Governance or Executive tab
- "Operating Review Pack" card
- month selector
- preview summary
- export button

ACCEPTANCE
- pack reconciles to month-end and close data
- signature deterministic
- review pack is executive-readable, not raw-ops clutter
