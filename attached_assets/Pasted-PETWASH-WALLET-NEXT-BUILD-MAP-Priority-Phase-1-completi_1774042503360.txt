3. FINANCIAL RULES
==================================================

A. HOLD
When hold is created:
- available_balance_cents decreases
- pending_balance_cents increases
- ledger entry_type = hold
- balance_after_cents records new available balance

B. RELEASE
When hold is released:
- available_balance_cents increases
- pending_balance_cents decreases
- ledger entry_type = release

C. DEBIT FROM HOLD
When booking becomes financially committed:
- pending_balance_cents decreases
- available_balance_cents does not change again
- ledger entry_type = debit
- lifetime_redeemed_cents increases

This is critical:
debitFromHold is NOT the same as direct debit.
The money already left available balance at hold time.

D. DIRECT DEBIT
Used for:
- K9000
- academy immediate purchase
- future instant checkout flows

When direct debit happens:
- available_balance_cents decreases
- pending_balance_cents unchanged
- ledger entry_type = debit
- lifetime_redeemed_cents increases

E. REFUND
When refund happens:
- available_balance_cents increases
- pending_balance_cents unchanged
- ledger entry_type = refund
- lifetime_earned_cents may or may not increase depending on your reporting policy
Recommended:
  - do NOT add refunds into lifetime_earned_cents
  - keep lifetime_earned_cents for true earned credits only
  - track refunds separately in reporting

==================================================
PHASE 2 - BOOKING HOLD / RELEASE / DEBIT FLOW
==================================================

5. BOOKING FLOW - CORRECT FINANCIAL LIFECYCLE

A. BOOKING CREATE
At booking creation:
1. calculate booking subtotal server-side
2. call previewRedemption with booking cap
3. if user chooses wallet usage:
   - create hold for approved amount
   - store wallet_hold_cents
   - store wallet_hold_key
   - set finance_state = hold_active
4. remaining amount paid by card / cash as your current logic dictates

B. BOOKING DECLINED BY PROVIDER
If hold active:
- call releaseHold
- store wallet_release_key
- set wallet_hold_cents still as historical value
- set finance_state = released

C. BOOKING CANCELLED BY CUSTOMER
If hold active and service not financially committed:
- release hold
- finance_state = released

If already debited and policy allows refund:
- refund
- finance_state = refunded

D. BOOKING EXPIRES / TIMES OUT
If hold active:
- release hold automatically
- finance_state = released

E. BOOKING CONFIRMED / SERVICE START
At the actual commitment moment:
- call debitFromHold
- store wallet_debit_key
- store wallet_debited_cents
- finance_state = debited

Choose one financial moment and keep it consistent:
Recommended:
- walkers / sitters: debit on confirmed booking if commercial commitment is final
OR
- debit on service start if cancellations are still common before service begins

Pick one rule and keep it universal.

==================================================
6. SERVER-SIDE BOOKING CAP RULES
==================================================

Wallet cap must not live only in UI.
It must be enforced server-side in previewRedemption.

Recommended rules:
- K9000: maxRedeemPct = 100
- walker / sitter booking: maxRedeemPct = 50
- academy: usually 100 unless business wants partial cap

Formula:
walletRedeemableMaxCents = min(
  available_balance_cents,
  floor(subtotalCents * maxRedeemPct / 100)
)

Example:
subtotal = 12,000
wallet balance = 50,000
maxRedeemPct = 50
walletRedeemableMax = 6,000
