PHASE 4.3 - EXECUTION INTELLIGENCE & CLOSED-LOOP OPERATIONS

GOAL
Turn the recommendation and action system from tracked workflow into measurable execution intelligence.
The platform should now:
- prioritize what should be acted on first
- measure whether actions actually worked
- surface bottlenecks before they become finance issues
- route follow-up automatically
- expose reviewer and operator quality trends
- connect outcomes back into confidence and policy tuning
- give management one execution-quality view across the whole stack

LOCKED PRINCIPLES
- no wallet-core changes
- no mutation of original financial facts
- every priority score must be explainable
- every automation remains auditable
- every quality score must be based on stored outcomes, not heuristics only
- every follow-up action must have owner, due date, and status
- all dashboards remain read-only unless an explicit action endpoint is called

==================================================
4.3A - RECOMMENDATION PRIORITY ENGINE
==================================================

GOAL
Rank recommendations by operational urgency and financial impact.

DB
Create table: recommendation_priority_scores
- id SERIAL PRIMARY KEY
- recommendation_id INTEGER NOT NULL
- priority_score NUMERIC(8,2) NOT NULL DEFAULT 0
- urgency_score NUMERIC(8,2) NOT NULL DEFAULT 0
- value_score NUMERIC(8,2) NOT NULL DEFAULT 0
- confidence_score NUMERIC(8,2) NOT NULL DEFAULT 0
- bottleneck_score NUMERIC(8,2) NOT NULL DEFAULT 0
- reasoning_json JSONB NOT NULL DEFAULT '{}'::jsonb
- created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()

BACKEND
- GET /api/prestige-pass/admin/wallet/recommendations/prioritized
- POST /api/prestige-pass/admin/wallet/recommendations/recompute-priority

FRONTEND
Command Center
- sort by priority
- show score chips
- "why this is prioritized" drawer

ACCEPTANCE
- same inputs give same score
- reasoning is visible to ops
- no hidden ranking logic

==================================================
4.3B - EXECUTION OUTCOME EFFECTIVENESS
==================================================

GOAL
Show which accepted actions actually improved the system.

DB
Use remediation_outcomes and add:
- effectiveness_score NUMERIC(8,2) DEFAULT 0
- effectiveness_reason TEXT DEFAULT ''

BACKEND
- GET /api/prestige-pass/admin/wallet/outcomes/effectiveness
Returns:
- improved count
- worsened count
- unchanged count
- average effectiveness
- top successful action types
- top failed action types

FRONTEND
Command Center / Governance
- effectiveness tiles
- before vs after comparison
- success/failure leaderboard by action type

ACCEPTANCE
- effectiveness is derived from actual before/after rows
- action types are comparable
- no manual classification needed for normal cases

==================================================
4.3C - FOLLOW-UP AUTOMATION & ESCALATION
==================================================

GOAL
Automatically create and escalate follow-up actions when remediation stalls.

DB
Extend review_follow_up_actions:
- escalated_at TIMESTAMPTZ
- escalation_level INTEGER NOT NULL DEFAULT 0
- blocked_reason TEXT DEFAULT ''

BACKEND
- POST /api/prestige-pass/admin/wallet/followups/auto-generate
- GET /api/prestige-pass/admin/wallet/followups
- PATCH /api/prestige-pass/admin/wallet/followups/:id
- JOB: escalate overdue follow-ups every hour

FRONTEND
Governance
- follow-up queue
- overdue badges
- escalation history
- assign / close / re-open

ACCEPTANCE
- overdue actions escalate once per level
- closed actions never escalate
- all escalations logged

==================================================
4.3D - REVIEWER / OPERATOR QUALITY ANALYTICS
==================================================

GOAL
Measure who resolves well, not just who acts quickly.

DB
Reuse reviewer_performance_snapshots and extend if needed:
- action_accept_rate
- action_success_rate
- average_time_to_resolution_hours
- followup_overdue_rate
- quality_band VARCHAR(16)

BACKEND
- GET /api/prestige-pass/admin/wallet/reviewer-analytics
- GET /api/prestige-pass/admin/wallet/reviewer-analytics/:uid

FRONTEND
Orchestration
- reviewer table
- quality band badges
- trend sparkline
- drill into one reviewer

ACCEPTANCE
- scores come from stored outcomes and actions
- reviewer trends are filterable by period
- one user can be inspected deeply

==================================================
4.3E - BOTTLENECK DETECTION
==================================================

GOAL
Detect where work is getting stuck across approvals, follow-ups, refunds, disputes, and reconciliation.

DB
No new table required initially

BACKEND
- GET /api/prestige-pass/admin/wallet/bottlenecks
Returns:
- approval backlog
- overdue follow-ups
- unresolved disputes by age
- stale support actions
- reconciliation exceptions by age
- top blocked owners

FRONTEND
Control Center
- bottleneck panel
- traffic-light status
- click-through to exact queue

ACCEPTANCE
- counts reconcile to source tabs
- blocked owners and queues are visible
- zero state is clear

==================================================
4.3F - UNIFIED EXECUTION TIMELINE
==================================================

GOAL
Show one timeline from recommendation to action to outcome to follow-up.

DB
Use unified_recommendations + related tables

BACKEND
- GET /api/prestige-pass/admin/wallet/execution-timeline/:recommendationId
Returns:
- recommendation
- actions
- approvals
- execution events
- outcomes
- follow-ups
- learning suggestions

FRONTEND
Command Center / Governance
- timeline drawer
- grouped event cards
- timestamps, actor, status, linked object IDs

ACCEPTANCE
- one recommendation has one traceable story
- all linked events appear in order
- no missing cross-links

==================================================
4.3G - MANAGEMENT EXECUTION REVIEW
==================================================

GOAL
Give leadership a periodic view of whether the operating system is improving.

DB
Optional cache table:
execution_review_snapshots
- id SERIAL PRIMARY KEY
- period_key VARCHAR(32) NOT NULL
- snapshot_json JSONB NOT NULL
- created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()

BACKEND
- GET /api/prestige-pass/admin/wallet/execution-review?period=weekly|monthly
Returns:
- recommendations created
- accepted rate
- completion rate
- improvement rate
- average effectiveness
- overdue follow-up count
- top bottlenecks
- top reviewers
- top policy-learning items

FRONTEND
Governance
- "Execution Review" card
- weekly/monthly selector
- export JSON button

ACCEPTANCE
- values reconcile to underlying modules
- review is readable by management
- export deterministic
