The right structure for you

Core Brain Services (shared by all)
	1.	Identity + Roles

	•	Customer
	•	Provider (sitter, driver, trainer)
	•	Station (kiosk)
	•	Admin, Finance, HR
	•	Franchise (optional later)

	2.	Wallet + Prepaid

	•	One wallet per customer (or gift wallet)
	•	Supports:
	•	money balance (ILS)
	•	credits per vertical (wash, driving, sitting, academy)
	•	expiry, lock/freeze, fraud flags
	•	Works for:
	•	e-gift
	•	wash packages
	•	promo credits

	3.	Ledger (money cycle)
Everything becomes a ledger transaction:

	•	wallet top-up (gift purchase)
	•	booking created
	•	authorization hold (optional)
	•	capture (when service starts or completes)
	•	provider earnings recorded
	•	payout settlement
	•	invoice and receipt issued
This is what makes finance and compliance clean.

	4.	Pricing + Fees Engine

	•	customer price (what the customer pays)
	•	provider payout (what provider receives)
	•	platform fee (margin)
	•	taxes/VAT handling rules
	•	cancel/no show fees rules per vertical

	5.	Compliance Invoicing

	•	Issue receipt or invoice for each capture
	•	Store immutable invoice payload + doc number + PDF link (from invoice provider)
	•	Monthly statements per customer, provider, franchise

Separate operations per vertical (but same booking engine)

Each vertical gets its own “booking policy” module:
	•	Sitting: availability calendar, meet and greet, multi-day, provider acceptance
	•	Driving: route, pickup, dropoff, driver assignment, live status
	•	Academy: scheduled classes, capacity, attendance
	•	Kiosk wash: immediate redeem, station status, bay side, timeout, start command

They all call the same core endpoints but pass platform and serviceType.

Money cycle that matches your business

A) Prepaid top-up (e-gift or package)

Customer pays online:
	1.	Payment provider capture
	2.	Wallet credited (money balance or service credits)
	3.	Receipt issued immediately

B) Customer books service

Booking created with price quote:
	•	If prepaid wallet exists: reserve funds (optional) or validate balance
	•	If pay-as-you-go: card authorization (optional)

C) Service starts and completes
	•	Kiosk wash: kiosk calls redeem, backend deducts, returns approved, kiosk starts
	•	Human service: when provider confirms completion, backend captures and deducts wallet

D) Provider payout
	•	Earnings recorded per completed booking
	•	Payout batched daily or weekly
	•	Statement generated for provider and franchise if needed

Key rule: the kiosk, apps, and providers never “decide” money. Only the Brain does.

How wash packages fit

	•	“5 washes” is credits.petwash += 5

	•	Or you can price by bay type: small dog uses 1, large uses 2

Same logic for driving: “10 rides” package, etc.
