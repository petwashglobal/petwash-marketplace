Critical business logic correction.

The onboarding flow must NOT be treated as a simple signup.
It is a trust, identity, brand, and activation flow.

==================================================
1. ACCOUNT CREATION IS NOT FULL ACTIVATION
==================================================

A user can create an account with:
- full name
- email
- mobile

But the account is NOT fully active until BOTH of these are completed:

Step 1:
Mobile verification with a unique one-time code

Step 2:
Email activation by clicking the activation link in the email
AND the email flow must clearly include agreement / confirmation of activation and acceptance

This means:
- mobile verified only = not fully active
- email verified only = not fully active
- both complete = active

==================================================
2. REQUIRED ACCOUNT STATES
==================================================

Use clear states:

- draft
- mobile_verified_only
- email_verified_only
- pending_full_activation
- active
- suspended
- deleted

Suggested simpler operational logic:
- created
- mobile_verified
- email_verified
- active

But active must only happen when both checks are complete.

==================================================
3. MOBILE VERIFICATION FLOW
==================================================

User enters:
- name
- email
- mobile

System sends OTP / one-time code to mobile.

Rules:
- code expires
- retry limit
- rate limit
- audit log
- resend logic
- lockout after too many failed attempts

If mobile verification succeeds:
- mark mobileVerifiedAt
- account still NOT fully active until email activation completes

==================================================
4. EMAIL ACTIVATION FLOW
==================================================

After signup, system sends a luxury branded welcome / activation email.

Email must contain:
- welcome headline
- activation button
- account confirmation language
- agreement / acceptance language
- link click required

Important:
The user must click the email activation link.
Do not treat email sent as email verified.

If clicked:
- mark emailVerifiedAt
- record acceptedTermsAt if this is part of activation
- record activationSource = email_link

==================================================
5. FINAL ACTIVATION RULE
==================================================

Only when both are true:
- mobileVerifiedAt exists
- emailVerifiedAt exists

Then:
- account status = active
- loyalty profile can activate
- wallet shell can activate
- prestige join can complete
- booking / redemption / provider actions can proceed

==================================================
6. IF ONE SIDE IS MISSING
==================================================

Case A:
mobile verified, email not clicked
→ status remains pending activation
→ can login maybe, but restricted
→ show banner:
  "Please activate your email to complete your account"

Case B:
email clicked, mobile not verified
→ status remains pending activation
→ show banner:
  "Please verify your mobile to complete your account"
