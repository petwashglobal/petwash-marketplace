Phase 4.6 — Go-Live, Verification & Safe Rollout

4.6A — End-to-End Proof Pass Engine (Critical)

What:
A deterministic system that runs full business flows and verifies outcomes automatically.

Flows to simulate:
	•	Booking → hold → capture → payout → batch → reconciliation
	•	Dispute → resolution → refund → clawback
	•	Recommendation → action → execution → outcome → feedback loop
	•	Forecast → batch → actual → variance → accuracy

DB:
e2e_proof_runs
	•	id
	•	run_type (full | payouts | disputes | recommendations)
	•	status (running | passed | failed)
	•	steps_json (each step + result)
	•	failures_json
	•	started_at
	•	completed_at

Backend:
	•	POST /admin/system/e2e/run
	•	GET /admin/system/e2e/:id
	•	GET /admin/system/e2e/history

Each run:
	•	executes real endpoints in sequence (safe sandbox mode)
	•	validates invariants:
	•	no negative balances
	•	totals match across tables
	•	batch totals = ledger totals
	•	no orphan records

UI (Control Center):
	•	“Run Full System Test” button
	•	Progress tracker (step-by-step)
	•	Result:
	•	✅ Passed (green)
	•	❌ Failed (with exact failing step)

4.6B — Production Config & Secrets Audit

What:
Verify nothing critical is misconfigured before go-live.

DB:
system_config_audit_runs
	•	id
	•	checks_json
	•	failures_json
	•	status
	•	created_at

Checks:
	•	All required ENV variables exist
	•	No test keys in production
	•	Payment provider keys valid
	•	Email provider configured
	•	Cron enabled flags correct
	•	Kill switches default OFF
	•	Admin roles exist

Backend:
	•	POST /admin/system/config-audit/run
	•	GET /admin/system/config-audit/latest

UI (Governance):
	•	“Run Config Audit”
	•	Checklist with:
	•	✅ valid
	•	⚠️ warning
	•	❌ critical

4.6D — Shadow Mode (Read-Only Live Simulation)

What:
Run the system with real data but no financial mutations.

Mechanism:
	•	Global flag: SHADOW_MODE=true

Behavior:
	•	All flows execute
	•	Writes redirected to:
	•	_shadow tables OR
	•	flagged records (is_shadow=true)
	•	No real payouts / refunds executed

DB:
shadow_activity_log
	•	id
	•	entity_type
	•	entity_id
	•	action
	•	expected_result
	•	actual_result
	•	mismatch_flag
	•	created_at

Backend:
	•	POST /admin/system/shadow/enable
	•	POST /admin/system/shadow/disable
	•	GET /admin/system/shadow/logs

UI (Control Center):
	•	Shadow Mode toggle (⚠️ yellow state)
	•	Mismatch dashboard:
	•	expected vs actual
