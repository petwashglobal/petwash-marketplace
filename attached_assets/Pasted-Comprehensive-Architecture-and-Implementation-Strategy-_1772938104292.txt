Technical Remediation of Signup Disruptions
The primary impediment reported by users is the failure to reach the consent window or a total breakdown of the redirect flow. This is frequently manifested as the "Unable to process request due to missing initial state" error, a phenomenon that has become pervasive in 2026 due to aggressive browser storage partitioning and the deprecation of third-party cookies in the latest mobile browsers.
Mechanism of the "Missing Initial State" Error
On Android devices, particularly those utilizing Chrome versions released in 2025 and 2026, the signInWithRedirect flow often attempts to store a temporary session state in a cross-origin iframe. Modern privacy protections treat this as a tracking vector and clear the session storage during the redirect transition from the identity provider (IdP) back to the application domain. This results in the Firebase SDK losing the cryptographic "nonce" required to validate the authentication response, leading to a null return from getRedirectResult.
To remediate this, Pet Wash Ltd must transition to using a custom domain for its authentication handlers. By mapping a subdomain such as auth.petwash.co.il to the Firebase project and configuring it as the authDomain in the client-side Firebase initialization, the authentication process is treated as a first-party interaction. This technical adjustment bypasses the storage partitioning barriers and ensures that the initial state is preserved across the redirect lifecycle.
Whitelisting and Domain Authorization Integrity
A secondary failure point is the "auth/unauthorized-domain" error. This occurs when the continue URL or the redirect handler origin is not explicitly authorized in the Firebase console. For a production environment like PetWash.co.il, the whitelist must be exhaustive, including the primary domain, all environment-specific subdomains, and the Firebase-hosted handler URLs.

Implementation via Backend Blocking Functions
The "strong code" solution for 2026 relies on server-side enforcement rather than client-side logic. By deploying an Identity Platform blocking function, specifically beforeUserCreated, the system can verify that a user has interacted with the consent window before the account is finalized in the database.

The mobile application presents a custom UI window (as seen in the provided images) where the user must check a box to accept the terms of Pet Wash Ltd [Image 1, Image 2].

This mechanism ensures that no account exists for an unconsented user, providing absolute legal coverage for Pet Wash Ltd and preventing "orphan" accounts that would otherwise require manual cleanup under Amendment 13's "Right of Erasure".

Architecture for Role-Based Signup: Club Members vs. Providers
The original request highlights two distinct user journeys: those joining the Pet Wash Prestige Club and external providers [Image 2]. Managing these two cohorts within a single project requires a robust Role-Based Access Control (RBAC) strategy using Custom Claims.
Custom Claims for User Segmentation
In the 2026 paradigm, roles should not be stored as simple fields in a Firestore document, as this adds latency and increases database read costs for every security check. Instead, roles are embedded as immutable key-value pairs within the user's JSON Web Token (JWT).
| User Role | Privilege Level | Technical Implementation |
|---|---|---|
| Prestige Member | Access to club discounts, loyalty points, and premium wash plans. | { prestige: true } claim assigned upon club subscription event. |
| External Provider | Access to service log management, partner dashboard, and payout tracking [Image 2]. | { provider: true } claim assigned after Pet Wash Ltd administrative review. |
| Administrator | Full oversight, user management, and manual role assignment. | { admin: true } claim assigned via secure backend script. |
These claims must be assigned in a secure server environment using the Firebase Admin SDK. For new signups, a Cloud Function can be triggered on user creation to assign a default "guest" role, which is later upgraded as the user completes the Prestige Club payment or the Provider onboarding.
Token Refresh Logic and Propagation
A significant technical hurdle in 2026 is the propagation delay of custom claims. When Pet Wash Ltd upgrades a user to the Prestige Club, the new claim is not immediately visible on the client device until the ID token is refreshed, which typically happens once per hour. To ensure a seamless "Time-to-Value" experience, the application must force a token refresh immediately after the role assignment by calling currentUser.getIdToken(true).
Platform-Specific Compliance and "Strong Code" Standards
Building a "2026-ready" application for iOS and Android requires navigating new platform-specific security mandates that did not exist in earlier versions of the Firebase SDK.
Android: Mandatory Developer Verification and Play Integrity
Starting in September 2026, Google has instituted a mandatory developer verification policy for all Android apps running on certified devices. For Pet Wash Ltd, this means the application will be blocked from installation unless the developer account is verified with a legal business name and address that matches the corporate registration 517145033.
Furthermore, the "strong code" requirement for Android involves the transition from the deprecated SafetyNet to the Play Integrity API. Phone authentication, which is prominently featured in the Pet Wash signup screen [Image 1], relies on Play Integrity to verify that the signup request originates from a legitimate, un-tampered device. If Play Integrity checks fail, the system falls back to a reCAPTCHA flow which, if improperly configured with missing SHA-1 fingerprints, will fail with the "auth/missing-client-identifier" error.
iOS: Apple Universal Links and Universal Authentication
On iOS, the 2026 standard for authentication links is the move to universal links hosted on a verified domain, following the shutdown of Firebase Dynamic Links in August 2025. Pet Wash Ltd must configure its apple-app-site-association file on the petwash.co.il domain to allow the Firebase SDK to handle email authentication links as native universal links.
The user interface for iOS must also account for the Face ID button shown in the prototype images [Image 1]. In 2026, this is implemented using Firebase's support for passkeys, which utilizes the device's secure enclave to provide a phishing-resistant, biometric authentication experience. This aligns with the "strong code" requirement by replacing vulnerable passwords with hardware-backed credentials.
