The right business logic

1. System of record

Must stay:
	•	PostgreSQL = records
	•	object storage = files
	•	backend = decisions
	•	admin dashboard = review and operations

2. Google Forms

Can be used only for one of these:
	•	optional lead capture
	•	backup intake form
	•	emergency fallback intake
	•	simple marketing / interest forms

But not for the real provider workflow.

Because the real workflow needs:
	•	statuses
	•	queue
	•	review notes
	•	inbox
	•	resubmission
	•	audit trail
	•	role permissions
	•	dashboards
	•	decision history

Google Forms alone is too weak for that.

C. Dashboard separation by role

1. Management dashboard

Management should see:
	•	total provider applications
	•	pending review count
	•	resubmission count
	•	approval rate
	•	rejection rate
	•	average review time
	•	queue aging
	•	reviewer workload
	•	fraud spikes
	•	email delivery failures
	•	KYC processing failures
	•	trends over time

Management dashboard should be more strategic, less operational.

2. Support / operations dashboard

Support should see:
	•	live queue
	•	applications assigned to me
	•	urgent cases
	•	overdue cases
	•	unread applicant messages
	•	resubmission waiting
	•	approve / reject controls

This is operational.

3. Provider dashboard

Provider should only see:
	•	application status
	•	messages
	•	requests for more documents
	•	upload replacement files
	•	approval outcome
	•	once approved, provider tools only

They must never see internal flags, admin notes, fraud analysis, or management views.

4. Loyalty member dashboard

Public member should only see:
	•	profile
	•	membership status
	•	5% club discount
	•	10% special discount if approved manually
	•	smart wallet
	•	transactions
	•	packages
	•	redemptions
	•	benefits

They must never see provider onboarding logic.

Smart wallet logic

Since you mentioned loyalty users and digital wallet, this must be clearly separated too.

	•	e-gift balance

	•	package balance
	•	last transactions
