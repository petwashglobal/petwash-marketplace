PHASE 6.12 — MULTI-CHANNEL WINBACK (SMS + WHATSAPP)

GOAL  
Turn the existing winback engine into a high-conversion, multi-channel system that uses SMS and WhatsApp as controlled extensions of the experiment layer, not separate systems.

CORE PRINCIPLE  
Channels are part of the experiment, not outside it.  
Every send must be attributable, measurable, and governed by the same rules already built:
- experiments  
- attribution  
- suppression  
- frequency caps  
- guardrails  

--------------------------------------------------

1. CHANNEL MODEL (EXTENDS EXISTING VARIANTS)

Instead of:
ctrl / v1 / v2

You now operate as:
ctrl_inapp  
v1_inapp  
v2_inapp  
v1_sms  
v2_sms  
v1_whatsapp  

Channel becomes a dimension of the experiment.

--------------------------------------------------

2. MINIMAL DATA EXTENSION

No new tables required.

Extend experiment_events usage:

- channel: 'inapp' | 'sms' | 'whatsapp'

This must be written on every:
- notification_sent
- opened
- clicked
- completed

--------------------------------------------------

3. PROCESSOR FLOW (CONTROLLED ESCALATION)

File:
server/jobs/winback-processor.ts

Flow per user:

1. Send IN-APP (existing)
2. If NOT opened after 6 hours → send SMS
3. If NOT clicked after 24 hours → send WhatsApp

Must respect:
- frequency cap (14 days)
- suppression rules
- paused variants
- promoted winner logic

Never send all channels at once.

--------------------------------------------------

4. SMS IMPLEMENTATION (FIRST PRIORITY)

Use:
Twilio (cloud communications platform)

Basic send:

await twilio.messages.create({
  to: user.phone,
  from: process.env.TWILIO_NUMBER,
  body: message,
});

--------------------------------------------------

5. TRACKING LINK (CRITICAL)

Every message must include a tracked URL:

https://petwash.app/w?e=winback_14d&v=v1&c=sms

Parameters:
e = experiment key  
v = variant  
c = channel  

--------------------------------------------------

6. TRACKING ROUTE

New route:

GET /w

Behavior:
- log "clicked" event in experiment_events
- include channel + variant
- redirect to /marketplace

Example:

insert experiment_events:
{
  experimentKey: e,
  userId,
  variant: v,
  event: 'clicked',
  channel: c
}

--------------------------------------------------

7. WHATSAPP IMPLEMENTATION (SECOND STEP)

Use:
WhatsApp Business Platform (Meta API)

Notes:
- requires template approval
- slower to launch
- higher engagement once active

Use same tracking links and same experiment system.

--------------------------------------------------

8. COST CONTROL (MANDATORY)

Add limits:

max_sms_per_day = 50  
max_whatsapp_per_day = 30  

Processor must enforce:
- stop sending when limit reached
- log skipped sends

Admin UI should show:
- daily usage
- estimated spend
- cost per conversion

--------------------------------------------------

9. ADMIN UI EXTENSION

In WinbackTab add:

Channel Performance Table:

Columns:
Variant | Channel | Sent | Clicked | Completed | Conversion %

This reveals:
- which channel performs best
- which copy works per channel

--------------------------------------------------

10. EXPECTED OUTCOME

Within 3–7 days:
- SMS outperforms in-app
- WhatsApp outperforms SMS
- urgency copy performs best on SMS
- social proof may perform better in-app

--------------------------------------------------

11. ROLLOUT ORDER

Step 1:
Enable SMS only (low cap)

Step 2:
Verify tracking and attribution

Step 3:
Enable fallback logic (6h / 24h)

Step 4:
Add WhatsApp

Step 5:
Observe data before scaling

--------------------------------------------------

12. FINAL RESULT

System becomes:
- multi-channel
- experiment-driven
- cost-controlled
- self-optimizing

This is where the platform moves from feature-complete to revenue-generating.
