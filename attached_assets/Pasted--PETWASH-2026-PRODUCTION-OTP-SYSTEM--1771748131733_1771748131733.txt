---------------------------------
1) OTP SEND ENDPOINT RULES
---------------------------------

Endpoint: POST /api/auth/otp/send

Input:
- phone_e164 (required)
- user_type (public | provider | staff_request)
- device_id (required)
- language (en | he)

Server Logic:

1. Validate E.164 phone format.
2. Rate limit:
   - max 3 OTP per phone per hour
   - max 15 OTP per IP per hour
   - max 10 OTP per device_id per hour
3. Generate 6-digit numeric OTP.
4. Hash OTP (never store plain code).
5. Store in DB:
   - otp_id
   - phone_e164
   - otp_hash
   - expires_at (now + 5 min)
   - attempts = 0
   - ip_address
   - device_id
   - trace_id
6. Send SMS via Twilio Messaging Service (NOT from: +number).
   Use messagingServiceSid.
7. Return:
{
  "success": true,
  "expiresIn": 300
}

---------------------------------
2) OTP VERIFY ENDPOINT RULES
---------------------------------

Endpoint: POST /api/auth/otp/verify

Input:
- otp_id
- code
- device_id

Server Logic:

1. Find OTP record.
2. Reject if:
   - expired
   - attempts >= 5
   - already used
3. Increment attempts if wrong.
4. Compare hash.
5. On success:
   - mark phone_verified = true
   - mark OTP used_at = now
   - generate membership_id (server-side ONLY if not exists)
   - determine onboarding path
   - send welcome SMS
   - log audit event

Lock Rule:
If attempts >= 5 → lock for 15 minutes.
