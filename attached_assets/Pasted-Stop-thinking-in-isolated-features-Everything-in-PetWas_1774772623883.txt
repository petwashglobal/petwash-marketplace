MASTER RULE

==================================================
1. ACCOUNT ACTIVATION (CUSTOMER)
==================================================

Flow:

User registers →
Mobile OTP verification →
Email activation click →
User becomes ACTIVE

Only ACTIVE users can:
- use wallet
- redeem e-gift
- book services
- use K9000 wallet redemption
- join loyalty / prestige

==================================================
2. BECOME PROVIDER FLOW
==================================================

Provider onboarding is NOT instant.

Flow:

Step 1:
User submits provider application

Step 2:
System sends SMS verification (OTP)

Step 3:
If OTP verified:
→ application moves to "submitted_verified"

Step 4:
Admin review:
- approve OR reject

Step 5:
If approved:
→ send EMAIL confirmation (luxury style)
→ provider status = approved
→ provider dashboard unlocked

If rejected:
→ send email with reason
→ allow resubmission

==================================================
PROVIDER STATUS STATES
==================================================

- draft
- submitted
- mobile_verified
- pending_review
- approved
- rejected
- suspended

==================================================
3. E-GIFT PURCHASE FLOW
==================================================

When user purchases an e-gift:

1. Validate payment
2. Create financial transaction
3. Create gift record
4. Write ledger entry
5. Send confirmation email to buyer
6. Send gift email to recipient
7. Log audit event

Fields:

gift_cards
- id
- senderUserId
- recipientEmail
- recipientName
- amountCents
- currency
- message
- status
- issuedAt
- expiresAt
- redeemedAt nullable

==================================================
4. E-GIFT REDEMPTION FLOW
==================================================

When recipient redeems:

1. Validate gift code
2. Check not expired
3. Check not already redeemed
4. Apply value to wallet
5. Write wallet ledger entry
6. Mark gift as redeemed
7. Send confirmation email
8. Update dashboard

CRITICAL:
- redemption must be idempotent
- cannot redeem twice
- must lock row during redemption

9. SECURITY + GDPR RULES (CRITICAL)
==================================================

DO NOT store sensitive identity documents.

Never store:
- passport copies
- driver license images
- תעודת זהות images

Allowed:
- temporary scan for verification ONLY
- no persistent storage
- no backups
- no logs with raw document data

If verification needed:
- use third-party or ephemeral processing
- store only result (verified / not verified)
- store reference ID, not the document

Always:
- encrypt sensitive fields
- log access
- restrict admin visibility
