PHASE 12.17 - CASH RECONCILIATION & TREASURY DISCIPLINE

GOAL
Ensure that every approved financial action results in a real, verified money movement.
This phase connects internal approvals to actual cash execution and bank reconciliation.

No assumptions. No silent failures. No invisible money gaps.

--------------------------------------------------
T171 - PAYOUT BATCHES (EXECUTION UNIT)
--------------------------------------------------

CREATE TABLE payout_batches (
  id SERIAL PRIMARY KEY,
  batch_ref TEXT UNIQUE NOT NULL,
  owner_scope TEXT NOT NULL,              -- 'company', 'franchise', 'station'
  owner_id TEXT NULL,
  total_amount_cents INTEGER NOT NULL,
  currency TEXT DEFAULT 'ILS',
  status TEXT NOT NULL,                   -- 'pending', 'approved', 'submitted', 'paid', 'failed', 'reconciled'
  created_at TIMESTAMP DEFAULT NOW(),
  approved_at TIMESTAMP NULL,
  submitted_at TIMESTAMP NULL,
  paid_at TIMESTAMP NULL,
  failed_at TIMESTAMP NULL,
  reconciled_at TIMESTAMP NULL
);

CREATE TABLE payout_batch_items (
  id SERIAL PRIMARY KEY,
  batch_id INTEGER REFERENCES payout_batches(id) ON DELETE CASCADE,
  settlement_id INTEGER NOT NULL,
  amount_cents INTEGER NOT NULL,
  status TEXT NOT NULL DEFAULT 'pending',  -- 'pending', 'submitted', 'paid', 'failed'
  created_at TIMESTAMP DEFAULT NOW()
);

RULE
Money is never sent individually. Everything moves through batches.

--------------------------------------------------
T172 - BANK TRANSACTION IMPORT
--------------------------------------------------

CREATE TABLE bank_transactions (
  id SERIAL PRIMARY KEY,
  bank_ref TEXT UNIQUE,
  amount_cents INTEGER NOT NULL,
  currency TEXT DEFAULT 'ILS',
  direction TEXT NOT NULL,                 -- 'outgoing', 'incoming'
  reference TEXT NULL,                    -- payout batch ref or external note
  raw_description TEXT NULL,
  value_date DATE,
  created_at TIMESTAMP DEFAULT NOW()
);

BUILD
- endpoint: POST /api/treasury/import-bank-transactions
- accepts CSV / JSON
- deduplicates by bank_ref

RULE
The bank is the source of truth for executed money.

--------------------------------------------------
T173 - RECONCILIATION ENGINE
--------------------------------------------------

CREATE TABLE reconciliation_results (
  id SERIAL PRIMARY KEY,
  batch_id INTEGER REFERENCES payout_batches(id),
  bank_transaction_id INTEGER REFERENCES bank_transactions(id),
  status TEXT NOT NULL,                   -- 'matched', 'partial', 'unmatched'
  amount_expected INTEGER,
  amount_actual INTEGER,
  difference_cents INTEGER,
  created_at TIMESTAMP DEFAULT NOW()
);

BUILD
server/lib/reconciliation.ts

LOGIC
For each payout batch:
- find bank transaction where:
  reference ~ batch_ref OR
  amount matches within tolerance

MATCH TYPES
- exact match → matched
- small delta → partial
- no match → unmatched

OUTPUT
{
  status,
  expected,
  actual,
  difference
}

--------------------------------------------------
T174 - FAILED PAYOUT HANDLING
--------------------------------------------------

CREATE TABLE payout_failures (
  id SERIAL PRIMARY KEY,
  batch_id INTEGER REFERENCES payout_batches(id),
  reason TEXT,
  retry_count INTEGER DEFAULT 0,
  last_retry_at TIMESTAMP NULL,
  resolved BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP DEFAULT NOW()
);

FLOW
If:
- bank transaction missing after threshold OR
- explicit failure detected

THEN:
- mark batch as failed
- insert into payout_failures
- block re-release until resolved

--------------------------------------------------

PROCESS

- create reconciliation_results rows

RULE
System continuously verifies money without manual trigger.

--------------------------------------------------
T178 - FINANCIAL INTEGRITY RULES
--------------------------------------------------

1. A payout batch cannot become "reconciled" unless matched
2. A batch marked "paid" must have a bank transaction
3. A failed batch cannot be re-released without explicit retry
4. Differences must be visible (no silent rounding)
5. Partial matches must be flagged, not accepted silently
