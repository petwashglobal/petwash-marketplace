🧱 Phase 4.7 — Full Spec (One Block)

4.7A — Real-Time Anomaly Detection Engine

What:
Continuously scans live system metrics and flags anomalies BEFORE they become incidents.

Detects:
	•	sudden spike in refunds
	•	payout imbalance
	•	reconciliation mismatch rate increase
	•	dispute surge
	•	alert silence (alerts not firing)

DB:
anomaly_events
	•	id
	•	anomaly_type
	•	severity (low | medium | high | critical)
	•	metric_value
	•	baseline_value
	•	deviation_pct
	•	status (open | acknowledged | resolved)
	•	detected_at
	•	resolved_at

Backend:
	•	GET /admin/system/anomalies
	•	POST /admin/system/anomalies/ack/:id
	•	POST /admin/system/anomalies/resolve/:id

Engine (cron every 5 min):
	•	compares live vs baseline (last 7–30 days)
	•	flags deviation > threshold

UI (Command Center):
	•	“Anomaly Feed”
	•	severity colored rows
	•	deviation % shown

⸻

Stop alert noise. Rank what actually matters.

	•	severity weight

	•	trend acceleration

DB:
alert_priority_scores

UI:

4.7C — Preemptive Kill Switch Triggers (Guarded)

What:
System can recommend OR trigger kill switches automatically.

Rules (example):
	•	payout mismatch > X → recommend stop payouts
	•	refund spike > Y → recommend stop refunds
	•	reconciliation failure → auto-stop batch creation

Modes:
	•	recommend_only
	•	auto_with_approval
	•	auto_execute (only for extreme cases)

DB:
kill_switch_triggers
	•	id
	•	trigger_type
	•	condition_json
	•	action (recommend | require_approval | auto)
	•	last_triggered_at

Backend:
	•	GET /admin/system/kill-switch/triggers
	•	POST /admin/system/kill-switch/override

UI (Control Center):
	•	“Suggested Actions” panel:
	•	⚠️ Stop payouts (confidence 92%)
	•	Approve / Ignore

⸻
