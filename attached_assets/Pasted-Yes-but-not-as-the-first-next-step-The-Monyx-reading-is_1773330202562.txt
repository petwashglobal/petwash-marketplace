Should you build the webhook handler?

Yes, but only after 3 prerequisites are confirmed:

1. Nayax webhook capability

You need Nayax to confirm they can send you:
	•	transaction approved
	•	transaction cancelled
	•	refund
	•	machine ID
	•	terminal ID
	•	timestamp
	•	payment channel
	•	customer identifier of some kind, if allowed

2. Identity mapping

This is the hardest part.
If a customer pays through the Monyx app directly, you may not automatically know which PetWash member they are.

So before you award PetWash loyalty points, you need one of these:
	•	phone-number matching with explicit consent
	•	linked Monyx wallet to PetWash account
	•	Nayax customer token that you can safely map
	•	a PetWash deep link handoff flow

Without identity mapping, webhook loyalty will be messy and unreliable.

3. Stability first

Before adding this layer, finish:
	•	Firestore escrow index fix
	•	walk_bookings schema crash fix
	•	walk_slot_holds persistence fix

Because loyalty on top of unstable bookings/payments is the wrong order.

Best smart business rule

This is the cleanest logic:

Channel A - PetWash native wallet / QR

User pays through PetWash app and scanner path:
	•	full PetWash loyalty
	•	full wallet rewards
	•	full gift logic
	•	best analytics
	•	best member identity

Channel B - Monyx direct payment

User scans machine QR with Monyx app:
	•	payment works
	•	PetWash points only if account is linked
	•	no advanced PetWash wallet bonus unless mapped to a PetWash member
	•	good fallback channel for casual users

That way you do not lose customers who want Monyx, but you still keep PetWash as the premium/member path.

What the webhook handler should do

When Nayax sends a transaction event:
	1.	Validate signature / secret
	2.	Deduplicate by external transaction ID
	3.	Confirm machine belongs to PetWash
	4.	Classify channel:
	•	petwash_wallet_qr
	•	monyx_qr
	•	tap_card
	•	apple_pay_google_pay
	5.	Match customer identity if possible
	6.	Create internal ledger event
	7.	Award loyalty only if rules pass
	8.	Never award twice
	9.	Handle refund reversals by reversing points if needed
