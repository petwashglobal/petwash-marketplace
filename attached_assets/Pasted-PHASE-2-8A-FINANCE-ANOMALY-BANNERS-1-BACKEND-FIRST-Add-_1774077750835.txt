PHASE 2.8A - FINANCE ANOMALY BANNERS

1. BACKEND FIRST
Add:
GET /api/prestige-pass/admin/wallet/anomalies

Return shape:
[
  {
    "code": "negative_balance" | "stale_hold" | "refund_exceeds_hold" | "double_debit",
    "severity": "critical" | "warning",
    "userId": "...",
    "bookingId": "...",
    "detail": "...",
    "detectedAt": "ISO"
  }
]

Rules:
- negative_balance
  - wallet accounts
  - available_balance_cents < 0 OR pending_balance_cents < 0
  - severity = critical

- stale_hold
  - booking_requests + trainer_bookings
  - finance_state = 'hold_active'
  - age > 48h
  - severity = warning

- refund_exceeds_hold
  - booking_requests + trainer_bookings
  - wallet_refunded_cents > wallet_hold_cents
  - severity = critical

- double_debit
  - wallet_ledger_entries
  - same booking_id appears in more than one debit row
  - severity = critical

Ordering:
- critical first
- then detectedAt DESC
- limit 50

2. SQL SHAPE
Build as 4 queries, normalize, then merge in memory.

Negative balances:
- wallet_accounts
- map to anomaly rows with bookingId = null

Stale holds:
- booking_requests
- trainer_bookings
- normalize bookingId
- detectedAt = created_at

Refund exceeds hold:
- both booking tables
- detectedAt = updated_at

Double debit:
- wallet_ledger_entries
- GROUP BY booking_id
- HAVING COUNT(*) > 1 for event_type = 'debit'
- userId from ledger rows if available

AdminWalletDashboard.tsx

Behavior:

Rendering:
