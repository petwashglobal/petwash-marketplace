2 – Handle provider sign‑up flow after authentication

After authentication (via SMS or OAuth), the app should determine whether the user is a provider and whether it is their first login:
	1.	In the authentication callback or onAuthStateChanged handler, check additionalUserInfo?.isNewUser and user.customClaims?.role.  If isNewUser is true or the role is undefined, assume this is a new provider.
	2.	Call a cloud function or API endpoint (e.g. /api/provider/onboard) to create the provider profile in the database.
	3.	Redirect the user to /provider/onboarding or another route to collect additional information (services offered, payment details, schedule).  Ensure this route exists in the router and is permitted.
	4.	For returning providers with completed profiles, redirect them to the provider dashboard /provider/home.
	5.	On mobile, use absolute paths (e.g. router.push('/provider/onboarding')) to avoid hash‑based route issues.  Test the flow on iOS Safari and Chrome for Android.

Summary

The PetWash mobile sign‑up issues are largely caused by the use of Firebase’s signInWithRedirect on a custom domain without configuring a same‑domain authDomain.  Modern browsers block third‑party cookies, causing the OAuth flow to fail ￼.  Additionally, the provider onboarding logic does not handle new users after SMS verification, leaving them on the login page.  Updating the Firebase configuration to use the app’s domain for authentication and implementing a proper post‑authentication onboarding flow will eliminate the login loops and allow providers to complete their registration.
