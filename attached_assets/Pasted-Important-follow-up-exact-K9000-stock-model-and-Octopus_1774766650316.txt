3. STATION-LEVEL STOCK FIRST
==================================================

Do not overcomplicate at first with per-bay stock unless physically necessary.

Phase 1:
Track most inventory at station level.

Reason:
- the two bays share one station structure
- refill staff usually replenish the station, not abstract bay inventory
- operations team needs practical visibility first

Later, if needed, we can track selected items per bay.

==================================================

==================================================

Every stock item should support:

- quantityOnHand
- unit

- targetLevel
- reorderLevel

Example:
shampoo
- quantityOnHand = 28
- unit = liters
- lowThreshold = 10

- targetLevel = 30
- reorderLevel = 8

This allows Octopus to generate real alerts.

==================================================
5. STOCK HEALTH RULES
==================================================

We need a clear health model.

Per item:
- healthy = above lowThreshold
- low = at or below lowThreshold
- critical = at or below criticalThreshold
- empty = 0

Per station:
- healthy = no critical items and no more than 2 low items
- warning = one or more low items
- critical = one or more critical items
- partial_service = item missing but station can still operate in reduced mode
- out_of_service = critical core consumable missing

Core consumables likely include:
- shampoo
- disinfectant
- water / pressure related consumables if relevant
- any must-have sanitation material

7. INVENTORY MOVEMENT RULES
==================================================

Every manual or automated stock change must be logged.

Examples:
- technician adds 20 liters shampoo
- system deducts estimated usage after 35 washes
- admin corrects bad count
- maintenance consumes spare hose
- station launched with opening inventory

Never just overwrite quantity without movement history.

==================================================
8. HOW STOCK SHOULD CHANGE
==================================================

Phase 1 practical logic:
Use estimated stock consumption per completed wash session.

Example:
For each completed wash:
- shampoo deduct estimated X ml
- disinfectant deduct estimated Y ml
- conditioner deduct estimated Z ml if that program was used

This can start as configurable estimation rules, not perfect sensor-driven metering.

Recommended config table:
station_consumption_rules
- id
- stationId nullable
- programType
- itemType
- estimatedConsumption
- unit
- isActive

This allows later tuning per station or per program.
