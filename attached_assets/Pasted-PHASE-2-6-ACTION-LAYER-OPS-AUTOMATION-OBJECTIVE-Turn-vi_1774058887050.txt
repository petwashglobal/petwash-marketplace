PHASE 2.6 — ACTION LAYER + OPS AUTOMATION

OBJECTIVE
Turn visibility → ACTION + AUTOMATION
Remove dev dependency from operations.

--------------------------------------------------
2.6A — ADMIN ACTIONS (CRITICAL)
--------------------------------------------------

A1 — Release / Refund (UI + API)

Endpoints:
POST /api/prestige-pass/admin/wallet/release
POST /api/prestige-pass/admin/wallet/refund

Payload:
{
  bookingId: string,
  amountCents?: number,
  reason: string
}

Release logic:
- require finance_state = 'hold_active'
- walletService.releaseBookingHold(...)
- update finance_state = 'released'

Refund logic:
- require finance_state = 'debited'
- walletService.refundBookingWallet(...)
- update:
  wallet_refunded_cents += amount
  finance_state = 'refunded' or 'partial_refunded'

Idempotency:
wallet:booking:release:admin:{bookingId}:{timestamp}
wallet:booking:refund:admin:{bookingId}:{timestamp}

Frontend (AdminWalletDashboard):
- Add buttons inside Booking Audit:
  [ Release Hold ]
  [ Refund ₪X ]
- Modal with reason + confirm
- Toast success / error

--------------------------------------------------
2.6C — STUCK-HOLD ESCALATION (AUTOMATION)
--------------------------------------------------

Trigger:
- walkers/sitters > 2h
- academy > 4h

Actions:
1. Twilio SMS:
[PetWash ALERT]
Stuck hold detected
Booking: {id}
Amount: ₪{amount}
User: {userId}
Division: {division}

2. (Optional) email later

Dedup:
- send once per booking
- column:
  stuck_hold_alert_sent_at

--------------------------------------------------
2.6D — DIVISION FINANCE CARDS (DASHBOARD)
--------------------------------------------------

Top cards:

- Total Redeemed Today
- Walkers Revenue
- Sitters Revenue
- Academy Revenue
- K9000 Revenue
- Pending Holds Total

Backend query:
SELECT division_code, SUM(amount)
FROM wallet_ledger
WHERE created_at >= NOW() - INTERVAL '24 hours'
GROUP BY division_code;
