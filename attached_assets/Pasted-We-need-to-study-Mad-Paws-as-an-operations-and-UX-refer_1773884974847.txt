- trust before booking

We are currently missing some of that structural logic.

I want a deep product audit and implementation plan based on the screenshots and app review, focused on what matters operationally.

We are missing important consent and settings structure.

We need a full consent framework, not only scattered toggles.

Required consent/settings architecture:
1. Terms of service acceptance
2. Privacy policy acceptance
3. Marketing consent opt-in / opt-out
4. Push notification permission flow
5. SMS notification preference
6. Email notification preference
7. Data export request path
8. Account deletion path
9. Privacy controls and data rights page
10. Consent log in backend with timestamps and versioning

We need to track:
- what user consented to
- when they consented
- which policy version
- whether they later withdrew consent

E. PROMO / COUPON / GIFT CARD / CREDIT LOGIC

We need one clean commercial logic for redemptions.

Customer can have:
- promo code
- gift card
- wallet credit
- referral credit
- prepaid package balance
- membership discount
- first-time discount
- senior discount if eligible

Redemption priority must be defined centrally by backend.
Suggested order:
1. coupon / promo eligibility check
2. gift card balance
3. wallet credit
4. remaining card charge / Nayax / payment method

We must never let frontend decide final payable amount.
Backend must calculate:
- subtotal
- discounts
- credits applied
- gift card applied
- tax if relevant
- final payable amount
- remaining stored balance

F. KIOSK / MACHINE / MOBILE REDEEM LOGIC

For kiosk redemption and machine usage, the logic must be smart and simple.

Possible customer flow:
1. user signs in
2. user has wallet / package / coupon / gift card / promo
3. user scans machine QR or machine ID
4. backend identifies machine
5. backend checks:
   - machine online
   - machine available
   - user authenticated
   - coupon eligibility
   - wallet / gift / balance
   - provider / location / campaign rules
6. backend shows final payment choice:
   - redeem credit
   - apply gift card
   - apply promo
   - pay remaining via Nayax / saved method
7. backend authorizes session
8. machine starts
9. session recorded
10. invoice / receipt / wallet update / loyalty update

We need a clear rule for partial payment:
- if stored value covers full wash, no card charge
- if not, charge only the balance
- user must see this clearly before start
