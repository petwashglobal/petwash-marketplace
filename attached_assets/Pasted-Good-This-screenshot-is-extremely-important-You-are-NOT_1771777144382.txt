Firebase Hosting IS correctly routing to Cloud Run

What Is Actually Happening

Flow right now:

Browser
→ petwash.co.il
→ Firebase Hosting rewrite
→ Cloud Run service
→ Cloud Run checks IAM
→ Request is NOT authenticated
→ Cloud Run returns 403 Forbidden

That is exactly what your screenshot shows.

So your backend exists.
Your routing likely exists.
Your backend is alive.
But Cloud Run is set to “Require authentication”.

For public APIs like /api/health and /api/provider-applications,
Cloud Run must allow unauthenticated access.

⸻

The Fix (This Is The Real One)

Go to:

Google Cloud Console
→ Cloud Run
→ Click your backend service (petwash-backend or similar)

Then:

Permissions
→ Add principal

Add:

allUsers
Role: Cloud Run Invoker

Save.

That is it.

This makes the service publicly invokable.

⸻

If You Prefer CLI (faster)

Run:

gcloud run services add-iam-policy-binding petwash-backend 
–region=me-west1 
–member=“allUsers” 
–role=“roles/run.invoker”

Replace:
	•	petwash-backend with your real service name
	•	me-west1 with your real region

⸻

After That

Wait 30 seconds.

Then reload:

https://petwash.co.il/api/health

You should now see:
200 OK

NOT 403.

Why This Was Blocking Provider Creation

Every provider registration call goes to:

/api/provider-applications
/api/auth/whoami
/api/consents
etc.

All of them were blocked by Cloud Run IAM.

So nothing could be created.

The red “offline” error was lying.
The real error is 403 Forbidden.

Important Security Note

Allowing allUsers to invoke Cloud Run does NOT mean:
	•	Your database is public
	•	Your admin endpoints are public

It just allows public HTTP access.

Your app-level auth (Firebase token verification) still protects sensitive routes.

This is the correct architecture for:
	•	Web app
	•	Public API
	•	OTP system
	•	Provider signup
	•	Booking flows
