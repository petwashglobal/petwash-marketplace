PHASE 6.13 — DEPLOYMENT & VERIFICATION CHECKLIST

GOAL  
Ensure the system is not just deployed, but:
- behaving correctly  
- measuring true lift  
- not leaking money  
- safe to scale  

--------------------------------------------------

1. PRE-DEPLOY SANITY CHECK

Verify environment variables:

- TWILIO_NUMBER set  
- SMS / WhatsApp daily caps configured  
- Timezone logic aligned (Israel time assumed)  
- Cron / scheduler running winback processor reliably  

Verify database:

- winback_queue.paused_at exists  
- winback_queue.pause_reason includes:
  control_group  
  over_messaged  
  losing  
- experiment_events logging channel field  
- experiment_decisions table populated  

--------------------------------------------------

2. CONTROL GROUP VERIFICATION (CRITICAL)

Action:
- Trigger proof-run OR wait for natural flow

Check:

- ~10% of eligible users are NOT receiving winbacks  
- experiment_events contains control_skip entries  
- winback_queue.pause_reason = 'control_group' appears  

Expected:

- Control users show:
  no send  
  no cost  
  still eligible for organic booking  

This is your baseline truth layer.

--------------------------------------------------

3. OVER-MESSAGING PROTECTION

Action:
- Identify user with ≥2 winbacks in last 30 days  

Check:

- New rows are NOT sent  
- pause_reason = 'over_messaged' is written  
- No SMS / WhatsApp triggered  

Expected:

- Hard cap enforced across ALL channels  

--------------------------------------------------

4. SMART TIMING VERIFICATION

Action:
- Run processor outside 18:00–21:00 window  

Check:

- scheduled_at gets moved to next valid window  
- Row is NOT processed immediately  

Expected:

- No messages sent outside window  
- No rows lost  

--------------------------------------------------

5. ESCALATION VARIANTS (TIMING A/B)

Action:
- Inspect experiment_events for timing patterns  

Check:

- Users split across:
  t0 (6h / 24h)  
  t1 (2h / 12h)  
  t2 (12h / 36h)  

Expected:

- Same user always gets same timing variant  
- Distribution roughly even  

--------------------------------------------------

6. OFFER SIZING (LTV)

Action:
- Pick 3 users:
  low LTV  
  mid LTV  
  high LTV  

Check:

- Credit amounts differ:
  <200 → lower  
  200–1000 → normal  
  >1000 → higher  

Expected:

- No overpaying low-value users  
- High-value users get stronger incentive  

--------------------------------------------------

7. CHANNEL TRACKING

Action:
- Click links from:
  in-app  
  SMS  
  WhatsApp  

Check:

- experiment_events logs:
  channel  
  variant  
  clicked  

Expected:

- Correct attribution per channel  

--------------------------------------------------

8. REVENUE ATTRIBUTION

Action:
- Complete booking after winback  

Check:

- winback_queue.converted_at set  
- booking linked within 7-day window  
- revenue appears in admin  

Expected:

- Conversion tied to correct channel  
- No double counting  

--------------------------------------------------

9. ROI TABLE VALIDATION

In WinbackTab verify:

Columns:

Channel | Conversions | Revenue | Cost | Profit | ROI

Check:

- Cost matches:
  SMS ~ $0.045  
  WhatsApp ~ $0.065  
- Profit = revenue - cost  
- ROI% calculated correctly  

Expected:

- Positive ROI on winning channel  
- Clear visibility of losses if any  

--------------------------------------------------

10. CONTROL VS TREATED COMPARISON

After 3–7 days:

Check:

- Control group conversion rate  
- Treated group conversion rate  

Expected:

- Treated > Control  

If NOT:
- stop scaling immediately  

--------------------------------------------------

11. DAILY MONITORING (FIRST WEEK)

Each day review:

- Sent volume vs cap  
- Click-through rate  
- Completion rate  
- ROI per channel  
- Pause reasons distribution  

Red flags:

- ROI negative  
- CTR drops sharply  
- Over-messaging spikes  

--------------------------------------------------

12. SAFE ROLLOUT PLAN

Day 1–3:
- Only winback_14d armed  
- Low caps  

Day 4–7:
- Observe funnel + ROI  
- Identify early winner  

After Day 7:
- Promote winning variant  
- Increase caps gradually  

Then:
- Enable 30d  
- Then 60d  

--------------------------------------------------

13. SUCCESS CRITERIA

System is ready to scale when:

- Control vs treated lift is clear  
- At least one variant >95% confidence  
- ROI positive per channel  
- No suppression anomalies  
- No user fatigue signals  

--------------------------------------------------

FINAL STATE

You now operate:

- a controlled experiment system  
- with real baseline  
- with profit visibility  
- with safety mechanisms  

This is not just deployed software.  
This is a live revenue engine under control.
