PART 1 - IDENTITY SYSTEM (CRITICAL)
-------------------------------------

The system must behave as ONE identity engine, not multiple separate login paths.

ENTRY METHODS (TARGET):
- Google
- Apple
- Phone (OTP)
- Email / Password
- Facebook (later)
- TikTok (later)
- Instagram (later)

RULE:
All methods must feed into ONE user account.

-------------------------------------
CORRECT LOGIN / SIGNUP LOGIC
-------------------------------------

When user chooses ANY method:

1. Authenticate with provider (Google, Apple, etc.)
2. Check if account already exists
3. IF exists:
   → sign in
4. IF not:
   → create account
5. Ask ONLY missing fields:
   - name (if missing)
   - phone (if missing)
   - consent (if missing)
6. Land user inside app

NO duplication
NO confusion
NO multiple identities

-------------------------------------
CURRENT PROBLEM
-------------------------------------

- Identity is partially unified, not complete
- Some methods work, others are partial or not wired
- Account linking is NOT properly implemented
- Same user can cause conflicts across login methods
- Errors like "user exists" are not handled properly

-------------------------------------
REQUIRED FIX
-------------------------------------

Implement full account linking logic:
- If same email / phone exists → LINK accounts
- Do NOT fail silently
- Do NOT create duplicates
