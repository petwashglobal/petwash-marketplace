PHASE 4.8C — AUTO-ACTION APPROVAL MODES
======================================

OBJECTIVE
---------
Introduce per-rule approval modes to control how self-healing actions execute:
- auto     → execute immediately
- notify   → do not execute, only alert
- manual   → require operator approval via remediation system

This converts self-healing into a governed system rather than blind automation.

--------------------------------------
1. DATABASE CHANGE
--------------------------------------

ALTER TABLE self_healing_rules
ADD COLUMN IF NOT EXISTS approval_mode VARCHAR(10) NOT NULL DEFAULT 'auto';

-- Allowed values:
-- 'auto' | 'notify' | 'manual'


--------------------------------------
2. EXECUTION LOG STATES (STANDARDIZE)
--------------------------------------

Ensure self_healing_executions.result supports:

- 'executed'
- 'notify_only'
- 'pending_manual'

(No migration required if using flexible string field)


--------------------------------------
3. CORE EXECUTION LOGIC (runSelfHealingCheck)
--------------------------------------

Replace the execution decision block with:

--------------------------------------------------

IF confidence_score < 40 THEN:
    → DO NOT execute
    → INSERT self_healing_executions:
        result = 'notify_only'
        result_note = 'Low confidence (<40)'
    → CREATE governance_alert
    → CONTINUE

ELSE:

    IF rule.approval_mode = 'auto' THEN:
        → EXECUTE ACTION
        → INSERT self_healing_executions:
            result = 'executed'

    ELSE IF rule.approval_mode = 'notify' THEN:
        → DO NOT execute
        → CREATE governance_alert
        → INSERT self_healing_executions:
            result = 'notify_only'
            result_note = 'Notify mode (no execution)'

    ELSE IF rule.approval_mode = 'manual' THEN:
        → DO NOT execute
        → CREATE remediation_suggestions row:

            INSERT INTO remediation_suggestions (
                source,
                rule_id,
                anomaly_event_id,
                confidence_score,
                suggested_action,
                status,
                created_at
            )
            VALUES (
                'self_healing',
                rule.id,
                anomaly.id,
                confidence_score,
                rule.action_type,
                'pending',
                NOW()
            );

        → INSERT self_healing_executions:
            result = 'pending_manual'
            result_note = 'Awaiting operator approval'

--------------------------------------------------

CRITICAL:
- NEVER execute action in manual mode
- ALWAYS log execution row (even if not executed)
- ALWAYS include confidence_score


--------------------------------------
4. GOVERNANCE ALERT BEHAVIOR
--------------------------------------

For BOTH:
- notify mode
- confidence < 40

Trigger:

INSERT INTO governance_alerts (
    alert_type,
    severity,
    message,
    triggered_by,
    created_at
)
VALUES (
    'self_healing_notify',
    'warning',
    'Self-healing action not executed (notify/manual mode)',
    'system',
    NOW()
);


--------------------------------------
5. BACKEND ROUTE (UPDATE RULE MODE)
--------------------------------------

PATCH /admin/system/self-healing/rules/:id/mode

Body:
{
  "approvalMode": "auto" | "notify" | "manual",
  "actor": "admin",
  "reason": "Switching to manual during stabilization"
}

Behavior:
- update self_healing_rules.approval_mode
- insert audit record into self_healing_rule_changes:

INSERT INTO self_healing_rule_changes (
    rule_id,
    changed_by,
    field_changed,
    old_value,
    new_value,
    reason
)
VALUES (...);


--------------------------------------
6. FRONTEND — RULE CARD
--------------------------------------

Add selector to each rule:

Mode:
[ Auto ▼ ]

Options:
- Auto (green)
- Notify (amber)
- Manual (blue)

On change:
→ call PATCH /rules/:id/mode
→ require reason input


--------------------------------------
7. FRONTEND — EXECUTION ROWS
--------------------------------------

Display execution state:

IF result === 'executed'
    → ⚡ Executed (green)

IF result === 'notify_only'
    → 🔔 Notified (amber)

IF result === 'pending_manual'
    → ⏳ Awaiting Approval (blue)

Also display:
- confidence badge (already built)
- rule name
- timestamp


--------------------------------------
8. REMEDIATION INTEGRATION (IMPORTANT)
--------------------------------------

Manual mode MUST reuse existing remediation system.

DO NOT:
- create new approval UI
- duplicate logic

Manual actions appear automatically in:
→ remediation panel (already built)


--------------------------------------
9. GUARDRAILS (MANDATORY)
--------------------------------------

- manual mode NEVER executes actions
- notify mode NEVER executes actions
- confidence < 40 ALWAYS overrides mode → notify_only
- every decision must be logged in self_healing_executions
- no silent skips


--------------------------------------
10. RESULTING SYSTEM BEHAVIOR
--------------------------------------

Each rule now behaves as:

| Mode    | Confidence | Outcome              |
|--------|------------|----------------------|
| auto   | ≥40        | execute              |
| auto   | <40        | notify_only          |
| notify | any        | notify_only          |
| manual | any        | pending_manual       |
