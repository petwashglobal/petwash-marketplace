SECTION 1 — SINGLE SOURCE OF TRUTH DATA CONTRACT
================================================================================

All layers MUST follow this structure exactly.

TypeScript Interface:

export type UserRegistration = {
  uid: string
  role: "customer" | "provider" | "external"
  firstName: string
  lastName: string
  email: string
  phone: string
  language: "he" | "en"
  address: {
    formatted: string
    street: string
    city: string
    postalCode: string
    country: string
    lat: number
    lng: number
  }
  createdAt: string
}

Backend validates this structure.
Database schema mirrors this structure.
Frontend maps into this structure.

NO FIELD DEVIATION ALLOWED.

SECTION 2 — DATABASE SCHEMA (POSTGRESQL)
================================================================================

CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  uid TEXT UNIQUE NOT NULL,
  role TEXT NOT NULL CHECK (role IN ('customer','provider','external')),
  first_name TEXT NOT NULL,
  last_name TEXT NOT NULL,
  email TEXT NOT NULL,
  phone TEXT,
  language TEXT DEFAULT 'he',

  formatted_address TEXT,
  street TEXT,
  city TEXT,
  postal_code TEXT,
  country TEXT,
  latitude NUMERIC,
  longitude NUMERIC,

  created_at TIMESTAMP DEFAULT NOW()
);

Indexes:
CREATE INDEX idx_users_uid ON users(uid);
CREATE INDEX idx_users_role ON users(role);
CREATE INDEX idx_users_city ON users(city);

SECTION 3 — GOOGLE PLACES INTEGRATION (CORRECT 2026 METHOD)
================================================================================

DO NOT hardcode language in script URL.

Correct script load:
https://maps.googleapis.com/maps/api/js?key=API_KEY&libraries=places

Let browser handle localization.

Autocomplete setup:

const autocomplete = new google.maps.places.Autocomplete(input, {
  componentRestrictions: { country: "il" },
  fields: ["address_components","geometry","formatted_address"]
});

Extract fields explicitly:

function parseAddress(place) {
  const components = place.address_components;

  const find = (type) =>
    components.find(c => c.types.includes(type))?.long_name || "";

  return {
    formatted: place.formatted_address,
    street: find("route"),
    city: find("locality"),
    postalCode: find("postal_code"),
    country: find("country"),
    lat: place.geometry.location.lat(),
    lng: place.geometry.location.lng()
  };
}

NEVER store raw Google object.
Store structured fields only.

SECTION 4 — ATOMIC REGISTRATION FLOW (CRITICAL)
================================================================================

Current broken model:
1. Firebase create user
2. Frontend sends data to backend
3. If backend fails → ghost account

Correct 2026 model:

STEP 1:
User registers via Firebase Auth.

STEP 2:
Cloud Function trigger executes:

exports.onAuthCreate = functions.auth.user().onCreate(async (user) => {
  try {
    const payload = await getTempRegistrationData(user.uid)

    validate(payload)

    await db.insertUser({
      uid: user.uid,
      ...payload
    })

    await markUserProfileCreated(user.uid)

  } catch (err) {
    await admin.auth().deleteUser(user.uid)
    logError(err)
  }
})

Result:
If DB insert fails → Firebase user deleted automatically.

NO ghost accounts.
NO partial state.

SECTION 5 — FRONTEND REGISTRATION LOGIC
================================================================================

1. Collect user data.
2. Parse address via Google.
3. Validate client-side.
4. Store temporary registration payload in secure Firestore doc:
   /pending_registrations/{uid}

5. Create Firebase Auth user.
6. Backend trigger finalizes creation.
7. Redirect only after profileCreated = true.

NEVER rely on frontend DB insert.
