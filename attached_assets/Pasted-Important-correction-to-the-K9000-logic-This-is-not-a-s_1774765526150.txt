Important correction to the K9000 logic.

This is not a single wash machine with one session path.
It is one PetWash station with TWO fully independent wash platforms / bays:

- Left wash bay
- Right wash bay

The middle cabinet contains the main board / central control area, but operationally each wash side is independent.

Each side has its own:
- QR reader
- credit card reader
- user flow
- wash session
- activation result
- status

This means:
- two different users can use left and right at different times
- two different users can also use left and right simultaneously if both sides are free
- each wash platform must be modeled as an independent operational unit

Critical rule:
Do not model the whole station as one single machine session.
Model it as:

Station
- stationId
- location
- centralController / main board

Wash Bay
- bayId
- stationId
- side: left / right
- qrReaderId
- cardReaderId
- status: ready / busy / fault / maintenance / offline
- currentSessionId nullable

Session
- sessionId
- bayId
- userId nullable
- source: terminal_card / wallet_qr / package / loyalty
- startedAt
- endedAt
- status

There is NO booking-time logic here.
This is not reservation-based.
This is instant walk-up self-service, open 24/7.

Correct usage flow:
1. Customer arrives physically
2. Sees which bay is free: left or right
3. Uses that side only
4. Pays by card or redeems by app / wallet QR
5. Only that selected bay starts
6. The other bay remains independent and available if free

So availability must be real-time bay status only, not booked timeslots.

Correct domain model should be:

stations
station_bays
bay_sessions
bay_telemetry
bay_faults
bay_payments
qr_tokens

NOT:
- bookings
- time reservations
- availability slots

For wallet QR flow:
- QR token must be tied to the exact bay, not just the whole station
- backend must validate:
  - station exists
  - bay exists
  - bay is ready
  - token matches exact bay
  - user wallet / package is valid
- if approved, start only that bay

For direct card flow:
- card payment on left starts left only
- card payment on right starts right only

Finance / reporting must distinguish:
- stationId
- bayId
- side (left/right)
- payment source
- session source

This is a real-time dual-bay self-service machine domain, not a booking platform.
