ARCHITECTURE

A. SEND-CODE STAGE

B. SECURITY MODEL
Do not hard-block phone OTP behind broken captcha.
Phone OTP is already a proof-of-possession flow.

Use this model:
- Turnstile / reCAPTCHA = best-effort anti-abuse signal
- rate limits + OTP + lockouts = hard security controls

Meaning:
- if Turnstile exists and passes, log it
- if Turnstile fails or is missing, do not break login
- still enforce:
  - per-IP send rate limit
  - per-phone send cap
  - verify-attempt cap
  - cooldown
  - abuse logging

This is how real systems are made resilient.

C. OTP CHALLENGE MODEL
Create a proper challenge record with:
- challenge_id
- phone_e164
- user_id if known
- otp_hash
- expires_at
- sent_at
- resend_count
- failed_attempts
- status
- ip
- device/session context

Never store raw OTP.
Hash only.

OTP RULES
- 6 digits
- 5 min expiry max
- one-time use
- old code invalidated when new code sent
- resend cooldown
- max resend count
- max verify attempts
- hard lock after repeated failures

- compare hash
