SAFE BACKUP & REPORTING ARCHITECTURE

IMPORTANT:
Google Sheets is NOT the database.
Postgres (or primary DB) is the system of record.
Sheets is export, reconciliation, monitoring, and operational backup only.

------------------------------------------------------------
2) GOOGLE SHEETS USAGE MODEL
------------------------------------------------------------

Sheets must be:

1) Read-only reporting (auto written by backend)
2) Append-only (never update in place for critical data)
3) Idempotent (avoid duplicate rows)

Backend must:
- Write via Google API
- Use service account, not manual OAuth
- Use idempotency key per row (booking_id, kyc_case_id, etc.)

Never:
- Use Sheets as primary storage
- Read business logic from Sheets
- Make decisions from Sheets data

------------------------------------------------------------

A) Daily Bookings Summary
Columns:

------------------------------------------------------------
4) EMAIL: support@petwash.co.il
------------------------------------------------------------

Use for:

A) System Alerts
- KYC failure rate spike
- Payment failure spike
- Station offline alert
- Security event (high risk login)
- Staff approval event

B) Daily Reports
- Bookings count
- Revenue summary
- Pending provider approvals
- Pending staff requests

C) Incident Alerts
- Suspicious velocity
- Fraud flag
- Repeated OTP abuse

Never:
- Send full KYC docs by email
- Send raw personal ID numbers
- Send full financial data in plain email

All emails:
- Template based
- Include trace_id
- Include link to secure admin panel

------------------------------------------------------------
5) BACKUP STRATEGY
------------------------------------------------------------

Primary backup:
- Database daily snapshot
- Stored in encrypted cloud storage

Secondary backup:
- Structured CSV export to Drive (daily)
- Encrypted ZIP
- Access controlled

Never rely on:
- Manual exports
- Someone downloading sheet manually

------------------------------------------------------------
6) GOOGLE SERVICE ACCOUNT CONFIGURATION
------------------------------------------------------------

Use:
- Dedicated service account
- JSON key stored securely (not in repo)
- Stored in environment secret manager

Permissions:
- Only specific folders
- Not entire Drive

Scopes:
- Drive file write
- Sheets append only

------------------------------------------------------------
7) COMPLIANCE AND LEGAL RISK MANAGEMENT
------------------------------------------------------------

Google Drive must NOT contain:

- Raw KYC documents (unless encrypted + strict TTL)
- Biometric data
- Full identity numbers

If using Drive for document temp storage:
- Use signed URL
- TTL auto-delete job
- Log deletion event in audit_events

------------------------------------------------------------
8) FAILOVER MODEL
------------------------------------------------------------

If:
- DB running → normal operations
- Sheets API fails → queue writes in DB retry table
- Email fails → retry queue with exponential backoff
- Drive fails → continue DB only, alert support

Never:
- Block user onboarding because Sheets failed
- Block booking because email failed
