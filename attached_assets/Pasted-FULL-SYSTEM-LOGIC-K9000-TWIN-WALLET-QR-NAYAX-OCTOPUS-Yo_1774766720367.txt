1. TWO COMPLETELY SEPARATE PAYMENT FLOWS
==================================================

You MUST NEVER MIX THESE FLOWS.

------------------------------------------
FLOW A - DIRECT PAYMENT (NAYAX TERMINAL)
------------------------------------------

User:
- walks to machine
- taps credit card / Apple Pay / Google Pay
- Nayax handles full payment (clearing, סליקה)
- machine starts immediately

System behavior:
- we DO NOT validate balance
- we DO NOT touch wallet
- we DO NOT block transaction
- Nayax is source of truth

We ONLY:
- receive webhook / event
- log k9000WashEvents:
  transaction_source = "nayax"
  redemption_source = "nayax"

------------------------------------------
FLOW B - WALLET / QR REDEMPTION
------------------------------------------

User:
- has wallet in app (ILS or credits)
- scans QR on machine
- app sends redeem request

Now WE control everything.

This must go through FULL validation:

1. Auth (user identity)
2. Wallet ownership
3. Balance / credits check
4. Machine exists
5. Machine is online
6. Station is not maintenance
7. Anti-fraud (max 3 per hour)
8. Prevent double redemption (nonce)
9. Atomic debit (transaction)

Only AFTER success:
→ send command to machine (START_PUMP)

Then log:
- wallet debit
- credit transaction
- k9000WashEvents
- audit ledger
