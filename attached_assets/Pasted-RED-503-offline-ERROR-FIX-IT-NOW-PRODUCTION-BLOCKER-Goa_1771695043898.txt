Example fetch wrapper (copy and adapt):

async function apiFetch(url, options = {}) {
  const attempt = async () => {
    const res = await fetch(url, {
      ...options,
      headers: {
        "Content-Type": "application/json",
        ...(options.headers || {}),
      },
      credentials: "include",
    });

    const traceId = res.headers.get("x-trace-id") || "";
    let body = null;
    try { body = await res.json(); } catch {}

    if (!res.ok) {
      const err = new Error(body?.message || "Request failed");
      err.status = res.status;
      err.traceId = traceId;
      err.body = body;
      throw err;
    }
    return body;
  };

  try {
    return await attempt();
  } catch (e) {
    const online = typeof navigator !== "undefined" ? navigator.onLine : true;

    if (!online) {
      e.userMessage = "No internet connection. Please try again.";
      throw e;
    }

    if (e.status === 503) {
      await new Promise(r => setTimeout(r, 800));
      return await attempt();
    }

    if (e.status === 401) e.userMessage = "Session expired. Please sign in again.";
    else if (e.status === 403) e.userMessage = "Not authorized.";
    else if (e.status === 429) e.userMessage = "Too many attempts. Please wait and try again.";
    else e.userMessage = "Something went wrong. Please try again.";

    throw e;
  }
}

STEP 3 - FIX THE REAL 503 CAUSE (backend)
------------------------------------------------------------
503 usually comes from one of these:

A) Cloud Run cold start or timeout
B) Route throws and your error handler returns 503
C) Upstream dependency down (DB, email, sheets, external API)
D) Bad health check or load balancer issue
E) CORS or preflight failing, client interprets as offline

3.1 Ensure EVERY API error response includes:
- status
- errorCode
- message
- traceId

3.2 Add an Express error middleware that never returns "offline":
app.use((err, req, res, next) => {
  const status = err.statusCode || err.status || 500;
  const traceId = req.traceId || res.getHeader("x-trace-id") || "";
  res.status(status).json({
    errorCode: err.code || "SERVER_ERROR",
    message: err.message || "Server error",
    traceId,
  });
});

3.3 Add structured logs for the failing route:
Log at start and end:
- traceId
- route
- userId (if any)
- duration_ms
- DB call durations
- external calls durations

3.4 Cloud Run settings (high impact):
- Minimum instances: 1 (avoid cold starts)
- Request timeout: increase if needed (ex 60s)
- CPU: always allocated (if available) to reduce cold start impact

3.5 If 503 happens during "legal consent submit":
Make the consent submit endpoint:
- idempotent using an idempotency key
- never depend on slow external services inside the request
- write to DB first
- queue any emails/sheets later
