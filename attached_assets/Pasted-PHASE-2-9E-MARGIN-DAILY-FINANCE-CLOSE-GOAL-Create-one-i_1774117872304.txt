PHASE 2.9E - MARGIN & DAILY FINANCE CLOSE

GOAL
Create one immutable daily close record per calendar day, with per-division snapshots and a hard close action only when finance is clean enough.

==================================================
1. DATABASE
==================================================

Create table:
finance_close_records
- id SERIAL PRIMARY KEY
- close_date DATE NOT NULL UNIQUE
- closed_by_uid VARCHAR(128)
- closed_at TIMESTAMPTZ
- division_snapshots JSONB NOT NULL DEFAULT '{}'::jsonb
- vat_liability_cents INTEGER NOT NULL DEFAULT 0
- exception_count INTEGER NOT NULL DEFAULT 0
- notes TEXT NOT NULL DEFAULT ''
- status VARCHAR(20) NOT NULL DEFAULT 'open'
- created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()

Indexes:
- UNIQUE(close_date)
- status
- created_at

==================================================
2. BACKEND ENDPOINTS
==================================================

A. GET /api/prestige-pass/admin/wallet/finance-close/:date
Purpose:
- fetch existing close record
- if none exists, scaffold today's close view from live data

Response shape:
{
  "record": {
    "closeDate": "2026-03-22",
    "status": "open",
    "closedByUid": null,
    "closedAt": null,
    "divisionSnapshots": {...},
    "vatLiabilityCents": 0,
    "exceptionCount": 0,
    "notes": ""
  },
  "checklist": {
    "noOpenAnomalies": { "ok": true, "count": 0 },
    "noStaleHolds": { "ok": true, "count": 0 },
    "noPendingDisputes": { "ok": true, "count": 0 },
    "noPendingRefundApprovals": { "ok": true, "count": 0 }
  }
}

Use existing sources:
- settlement-summary logic
- anomaly logic
- disputes list
- refund approvals pending queue

B. POST /api/prestige-pass/admin/wallet/finance-close/:date/close
Rules:
- admin only
- idempotent
- if already closed -> return existing row unchanged
- only succeeds when all checklist items are ok
- writes:
  - closed_by_uid
  - closed_at
  - division_snapshots
  - vat_liability_cents
  - exception_count
  - status = 'closed'
  - notes

C. GET /api/prestige-pass/admin/wallet/finance-close/history
Returns:
- last 30 close records
- newest first

==================================================
5. ACCEPTANCE
==================================================

A. Scaffold
- request today when no row exists
- returns status=open and live checklist

B. Block close
- insert one pending refund approval
- close endpoint must reject with 422

C. Successful close
- clear blockers
- close succeeds
- row inserted with immutable snapshot

D. Idempotency
- call close again for same date
- returns existing closed row, no duplicate insert

E. History
- closed day appears in history immediately

==================================================
6. IMPORTANT IMPLEMENTATION RULES
==================================================

- close_date is Jerusalem calendar date, not UTC date
- close endpoint is read-only until final insert
- all checklist sources must be reused, not re-invented
- no silent auto-close
- once closed, row is immutable for this phase

==================================================
7. BEST BUILD ORDER
