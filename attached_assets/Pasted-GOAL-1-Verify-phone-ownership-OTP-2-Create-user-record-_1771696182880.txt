GOAL
1) Verify phone ownership (OTP)
2) Create user record + assign unique Membership ID (server-side)
3) Send welcome message with Membership ID
4) Save evidence: message content, timestamps, provider used, consent flags, IP/device, delivery status

A) REQUIRED BACKEND LOGIC (minimal, fintech-grade)

1) On "Start phone login / register"
- Input: phoneE164, userTypeIntent (PUBLIC | PROVIDER | STAFF_REQUEST)
- Create/Upsert user by phone
- Generate OTP: 6 digits, ttl 5 minutes, max attempts 5, resend cooldown 60s
- Store:
  otp_id, phone_e164, otp_hash (never store plain OTP), expires_at, attempts, created_at, provider_message_id (if available), ip, user_agent, device_id
- Send OTP SMS using your provider
- Return: otp_id

2) On "Verify OTP"
- Validate otp_id + code matches otp_hash and not expired and attempts not exceeded
- Mark phone_verified = true
- If user has NO membership_id yet:
  generate membership_id server-side (never from client)
- Save membership_id on user record
- Determine onboarding path:
  PUBLIC -> complete profile (basic) + optional loyalty enrollment
  PROVIDER -> provider onboarding + KYC
  STAFF_REQUEST -> staff request submitted + pending admin approval
- Send Welcome SMS (template by userType) with membership_id
- Store full evidence of the welcome message send:
  message_type=WELCOME, template_id, rendered_text, to_phone, provider_response, provider_message_id, status, sent_at, delivered_at (if webhook), trace_id

3) Membership ID format (simple + scalable)
Pick one consistent format, examples:
- PW-IL-00012345 (country + padded)
- PW-2026-IL-7F3K9Q (year + country + short code)
Rules:
- Unique index in DB
- Never reassign
- Use same ID across email, SMS, support tickets, internal tools

B) OTP SMS TEMPLATES (first message)

1) PUBLIC USER OTP
"PetWash: Your verification code is {{CODE}}. Expires in 5 minutes. Do not share this code. Ref: {{TRACE}}"

2) PROVIDER OTP
"PetWash Provider: Your verification code is {{CODE}}. Expires in 5 minutes. Ref: {{TRACE}}"

3) STAFF OTP (request access)
"PetWash Staff Access: Your verification code is {{CODE}}. Expires in 5 minutes. Ref: {{TRACE}}"

C) WELCOME SMS TEMPLATES (after OTP verified)

1) PUBLIC USER WELCOME
"Welcome to PetWash. Your Member ID is {{MEMBER_ID}}. Complete your profile here: {{LINK_PROFILE}} Support: support@petwash.co.il"

2) PROVIDER WELCOME
"Welcome to PetWash Providers. Your Provider ID is {{MEMBER_ID}}. Start onboarding: {{LINK_ONBOARD}} ID verification is required to go live. Support: support@petwash.co.il"

3) STAFF WELCOME (PENDING APPROVAL)
"PetWash Staff Request received. Your Staff Request ID is {{MEMBER_ID}}. Access will be enabled after approval. Status: {{LINK_STATUS}} Support: support@petwash.co.il"

D) WHAT MUST BE STORED (legal + ops evidence)

For OTP event:
- event_type = OTP_SENT
- phone_e164
- otp_id
- expires_at
- provider (Twilio/other)
- provider_message_id
- ip, user_agent, device_id
- country_selected (if you use phone selector allowlist)
- trace_id

For OTP verification:
- event_type = OTP_VERIFIED (or OTP_FAILED)
- phone_e164
- otp_id
- result (success/fail reason)
- attempts_count
- ip, user_agent, device_id
- trace_id

For welcome message:
- event_type = WELCOME_SENT
- user_id
- membership_id
- user_type (PUBLIC/PROVIDER/STAFF_REQUEST)
- rendered_message_text (store exact text sent)
- template_id + template_version
- provider_message_id + status
- timestamps (sent_at, delivered_at if available)
- trace_id

For consent (recommended):
- consent_version_terms
- consent_version_privacy
- consent_timestamp
- consent_channel (web + sms)
- consent_evidence_hash (optional, but strong)

E) IMPORTANT NOTES
- Staff should NEVER get staff role on signup. They get STAFF_REQUEST only. Admin approval required.
- Provider welcome should NOT claim "approved" until KYC and review are done.
- Public welcome should push profile completion (DOB, full name, address) before bookings/wallet if required by your policy.
