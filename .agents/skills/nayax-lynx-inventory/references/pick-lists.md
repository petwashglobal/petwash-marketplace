# Pick Lists

## What a pick list is

A pick list is a machine-specific restocking guide generated by the Nayax system. It uses current stock levels and sales data to identify which products need to be collected from the warehouse and in what quantities, so that a technician can restock the machine efficiently in a single trip. Pick lists are generated per machine.

## Endpoints

| Method | Path | Purpose |
| ------ | ---- | ------- |
| POST | `/v1/machines/{MachineID}/pickLists` | Generate a new pick list for a machine |
| GET | `/v1/machines/{MachineID}/pickList` | Retrieve the current pick list for a machine |
| PUT | `/v1/machines/{MachineID}/pickList` | Update an existing pick list |
| DELETE | `/v1/machines/{MachineID}/pickList` | Delete the pick list for a machine |

Note the path difference: the POST endpoint uses `pickLists` (plural) while GET, PUT, and DELETE use `pickList` (singular).

## Create a pick list

No request body is required.

```
POST /v1/machines/<MachineID>/pickLists
Authorization: Bearer <your-token>
```

**Response (200 OK):**

```
(empty body)
```

**An empty response body is the expected success state.** The API returns `200 OK` with no body when the pick list is successfully created. Do not treat an empty body as an error.

To confirm the pick list was created, follow up with a GET request.

## Get a pick list

```
GET /v1/machines/<MachineID>/pickList
Authorization: Bearer <your-token>
```

**Response (200 OK):**

```json
[]
```

An empty array means the machine has no outstanding stock requirements at this time (either the machine is fully stocked or no pick list has been generated yet). A populated array contains product objects identifying what needs restocking and in what quantity.

## Update a pick list

```json
PUT /v1/machines/<MachineID>/pickList
Authorization: Bearer <your-token>

{
  "Products": [
    {
      "NayaxProductID": "<NayaxProductID>",
      "PickQuantity": 10
    }
  ]
}
```

**The `Products` array must contain at least one item.** An empty array (`"Products": []`) is not accepted, so always include at least one product object.

## Delete a pick list

```
DELETE /v1/machines/<MachineID>/pickList
Authorization: Bearer <your-token>
```

Removes the pick list for the specified machine. The machine must have an existing pick list or the request returns an error.

## Traps to avoid

- **Do not interpret an empty create response as a failure.** `POST /v1/machines/{MachineID}/pickLists` always returns 200 with no body on success. If you need confirmation, call `GET /v1/machines/{MachineID}/pickList` immediately after.
- **Never send an empty `Products` array on update.** `PUT` with `"Products": []` is not accepted. Always include at least one product when updating.
- **Machine products must be mapped before a meaningful pick list is generated.** If a machine has no products assigned (step 3 of the workflow), the generated pick list will be empty.
- **Note the path difference.** POST uses `pickLists` (plural); GET, PUT, and DELETE use `pickList` (singular). Using the wrong path returns 404.
